# Spec：Comic-Viewer MVP（安卓漫画阅读器）

> 权威版本：本文件（docs/SPEC.md）。跟踪面：GitHub Issue #1（已关闭）。两者同步更新。

## Problem Statement

我在 Windows 上把漫画库整理好（目录命名、排序都符合 Windows 资源管理器规则），再 rsync 到 Linux NAS。在安卓设备上至今没有一款完全符合我使用习惯的漫画阅读器：浏览 NAS（SMB/WebDAV）、连 Komga、条漫阅读、蓝牙鼠标操作、精确到页的跳转预览、与 Windows 一致的排序——这些散落在不同 APP 里，或行为对不上（尤其是排序规则与封面/进度呈现）。Perfect Viewer 最接近但闭源且若干交互不可定制。

## Solution

Comic-Viewer：一款按我的习惯定制的安卓原生漫画阅读器。

- **四来源统一浏览**：本地存储（SAF）、SMB、WebDAV、Komga，同一套浏览/排序/阅读体验
- **两种阅读模式**：条漫（垂直连续滚动）与单页（LTR/RTL）
- **蓝牙鼠标全支持**：滚轮滚动/翻页、左右键、后退/前进侧键
- **Windows 一致的名称自然排序**与全来源通用的时间排序（修改时间/发布时间）
- **Perfect Viewer 风格交互**：触摸区域类型 3（纵向三等分）、双击放大、跳页网格预览、上一本/下一本
- **进度管理**：本地持久化 + Komga 双向同步；列表进度条（绿=进行中、红满格=读完）
- **书柜按连接分柜**（同一来源的多个连接也不混排，我点击某个连接**直接进入该连接的浏览页根层**——票 #49），封面自动取首页图；根层陈列该连接的根条目（文件源的文件夹与根下的书、Komga 的系列）；不再有逐本「加入书柜」的动作

技术底座：Kotlin + Jetpack Compose，minSdk 26。

## User Stories

> 故事编号是稳定锚点：删除的故事留空号、不重排（代码注释里的「spec 故事 N」据此长期有效）；新增故事一律在末尾追加新编号。

### 来源与连接

1. 作为漫画读者，我想添加 SMB 连接（服务器地址可含端口、路径=共享名/子目录、用户名/密码），以便浏览 NAS 上的漫画库
2. 作为漫画读者，我想添加 WebDAV 连接（URL、凭据），以便浏览支持 WebDAV 的网盘/NAS
3. 作为漫画读者，我想添加 Komga 连接（服务器地址 + 凭据），以便浏览我的 Komga 服务器
5. 作为漫画读者，我想通过系统文件夹选择器（SAF）授权本地文件夹，以便阅读手机/平板内的漫画而不必授予全盘权限
6. 作为漫画读者，我想在同一来源下建立多个连接，以便同时访问多台 NAS/多个账号
7. 作为漫画读者，我想编辑和删除已有连接，以便维护我的来源列表
8. 作为漫画读者，当连接失败时我想看到明确的错误原因（地址不通/认证失败/超时），以便自行修正

### 浏览与排序

9. 作为漫画读者，我想在浏览列表看到每个条目的封面——书取其第一页，**本层有图的容器（票 #97 起「图片+子文件夹/压缩包」这类目录是容器）取其本层首图**，多子文件夹的文件夹从第一层起逐级下取，**每一层都按与单层目录同一套优先级**（本层图 → 本层首个压缩包的首帧，票 #102）直到取到，以便一眼认出漫画
10. 作为漫画读者，我想按名称自然排序浏览，规则与 Windows 资源管理器一致——特殊字符先于数字、数字先于字母、假名先于汉字、数字按数值比较（第2话 < 第10话）、字母不区分大小写、假名按五十音序（平假名与片假名同权）、汉字按拼音——以便 APP 里的顺序和我电脑上整理的完全一致
11. 作为漫画读者，我想按修改时间排序（文件 mtime），以便定位最近更新过的内容
12. 作为漫画读者，我想按发布时间排序（书的发布日期，来自 CBZ 内 ComicInfo.xml 的 Year/Month/Day），以便按出版顺序阅读
13. 作为漫画读者，当书没有发布日期元数据时（如图片文件夹），发布时间排序应回退为修改时间排序，以便排序始终可用
14. 作为漫画读者，我要求全部四种来源都支持名称/修改时间/发布时间三种排序，以便体验一致（Komga 的发布时间排序走服务器端 sort=metadata.releaseDate；修改时间用服务器记录的文件修改时间）；**排序方式与方向是全局一份设置**——三种排序各自带方向（正向 / 反向，默认方向=现状：名称 A→Z、时间类新→旧），点当前排序类别再点一次即反向、按钮文字体现方向，选定后跨目录层级、跨连接、跨重启保持，浏览列表与书柜柜内读写同一份，以便整理时的排序口径全 app 一致
15. 作为漫画读者，我想在 Komga 来源按 系列 → 书 两级结构浏览，以便符合 Komga 的组织方式
16. 作为漫画读者，我想在浏览列表看到已读书目名称正下方的进度条（在名称那一列内、与名称左缘对齐；网格档则是压在封面下缘；部分填充绿色=进行中，满格红色=读完），以便了解之前读到哪里
17. 作为漫画读者，在混合目录（既有图片又有子文件夹）中我想点击图片条目后从该图开始按自然排序连读本目录图片，以便灵活入书（**票 #97**：混合目录因此是**容器**——点它先进浏览列表，本层图片与子文件夹都在列表里各自可选）
18. 作为漫画读者，在混合目录中我想点击含图片的子文件夹后按顺序阅读它，以便直接进入那一话（**票 #97**：只含图片的子文件夹才是书，在列表里直接打开）
19. 作为漫画读者，我想在浏览层级间前进/后退（全面屏返回手势与鼠标后退侧键=后退，前进侧键=前进），以便快速往返于层级 A/B 之间
22. 作为漫画读者，我想用鼠标滚轮在 APP 的各个列表界面滚动，以便不碰屏幕也能浏览

### 阅读器

23. 作为漫画读者，我想用条漫模式阅读（垂直连续滚动、**票 #89 起**可按页跳转：跳到下一页/上一页页首），以便看 webtoon 类作品
24. 作为漫画读者，我想用单页模式阅读并选择左→右或右→左（RTL）方向，以便看日漫扫描本
25. 作为漫画读者，我想在设置里切换阅读模式（菜单里不放切换入口），以便阅读期间不被误触
26. 作为漫画读者，我想让触摸区域按类型 3 划分——屏幕纵向三等分，且两种模式、两个单页方向下规则完全统一（左区恒为上一页、右区恒为下一页，不随 RTL 镜像）：左区=上一页（条漫=上一张图）、中区=呼出菜单、右区=下一页（条漫=下一张图），以便肌肉记忆一致
27. 作为漫画读者，在第一页点左区、最后一页点右区触发上/下一本时，我想先在底部弹出确认条（左=当前位置如「第一页」，右=橙色跳转按钮如「上一本书」，参考 3.jpg），点击该按钮才真正跳转，以便杜绝误触跳书；而阅读菜单底部的上一本/下一本按钮则直接执行、无需确认，以便明确意图时一步到位
28. 作为漫画读者，我要求相邻书的判定只由名称自然排序决定（与当前列表排序方式及方向都无关），范围=同一目录（文件源）或同一系列（Komga）；已到头时点击不置灰，而是弹提示「无上一本」/「无下一本」，以便上一本/下一本顺序可预期且到头有明确反馈（**票 #93 起**：该层本会话还没被列过时也弹同一条提示——邻位未知期与「确实到头」表现相同；进入阅读器后**后台**补齐该层，补齐后邻位即恢复）
29. 作为漫画读者，我想点击屏幕中区呼出阅读菜单：面板贴屏幕底部、半透明（不铺满全屏深色遮罩，当前页仍可见），含书名标题、跳页滑动条、当前页/总页数、上一本/下一本按钮（无返回按钮、无模式切换、无设置入口），以便界面干净且不打断阅读
30. 作为漫画读者，我想在打开阅读菜单时即看到当前页 ±2 的网格页面预览（带页码、当前页高亮），拖动滑动条时预览跟随目标页、松手后回到当前页，以便不必先拖动就能看清附近几页（**票 #87 起**：条漫模式的「当前页」= 顶部可见页；已滚到书末且内容超过一屏时报最后一页，末页矮于视口时高亮/页码不再停在倒数第二页）
31. 作为漫画读者，我想双击放大（以双击位置为中心，倍率默认 2.0x、可设 1.5x–4.0x），以便看清细节
32. 作为漫画读者，我要求放大状态按页记忆——翻页/回翻不复位，仅再次双击恢复适屏，且退出阅读器后放大状态丢弃（重开漫画看到原样），以便长篇细读时不用反复放大
33. 作为漫画读者，我想双指开合缩放（1x–8x、力度随手势），以便自由控制缩放
34. 作为漫画读者，放大后我想单指拖动平移（条漫=水平平移+垂直继续滚动；单页=限制在图片边界内），以便查看局部
35. 作为漫画读者，我想用蓝牙鼠标滚轮在阅读器内滚动页面（单页模式一格=翻一页），以便解放左手
36. 作为漫画读者，我想让鼠标左键等同触摸区域行为、右键与左键一致，以便只用鼠标也能完成全部阅读操作
37. 作为漫画读者，我想让鼠标后退侧键=浏览历史后退、前进侧键=浏览历史前进（前进不回到阅读器），以便导航符合系统习惯
38. 作为漫画读者，我想让 APP 适配全面屏返回手势（阅读器内不做返回按钮），以便符合现代安卓习惯
39. 作为漫画读者，我想用音量键翻页（单页=翻一页；**票 #89 起**条漫=跳到下一页/上一页的**页首**——一次按压一页，可能跳过当前页尚未显示的部分；**单击一跳、长按连发每一发都跳一页**；到书首/书末不交还系统，而是就地弹出**跨书上/下一本确认**（与点左区/右区同一动作，按键仍被消费、不改系统音量）；默认开、设置可关），以便单手阅读
40. 作为漫画读者，我想打开设置开关「始终从第一页打开」后，打开任何书都定位到第 1 页，且打开瞬间阅读进度即覆盖为第 1 页（进入马上退出也只算读了 1 页），以便重读时干净开始
41. 作为漫画读者，我想让阅读进度本地持久保存，以便任何来源的书重开时继续阅读
42. 作为漫画读者，Komga 来源的阅读进度我想与服务器双向同步（打开书时拉取定位、阅读中回传页码），以便手机/平板/网页多端无缝继续阅读

### 书柜与启动

43. 作为漫画读者，我想在书柜里按连接看到该连接的**根条目**，以便不逐本收藏也能有统一入口
44. 作为漫画读者，我要求书柜按连接分柜展示（同一来源的多个连接也不混排，我点击某个连接进入它——**票 #49 起直接进该连接的浏览页根层**：与首页点连接同一路由、同一屏、同一排版与同一标题口径，不再有独立的「单柜」屏；柜列表这一级在只有一个连接时同样保留），以便库与库之间不互相污染
45. 作为漫画读者，我想在书柜里看到与浏览列表一致的**书条目**进度条（绿=进行中、红满格=读完，不是红勾；文件夹与系列没有进度，不显示），以便掌握全局进度
46. 作为漫画读者，我想设置启动页面，选项：上次阅读的位置（默认）/ 上次停留的位置 / 书柜 / 阅读器 / 首页，以便按当天心情选择起点
47. 作为漫画读者，我要求「上次阅读的位置」在上次退出时正在看书才直接打开该书并定位到上次页码，否则退化为恢复上次停留的浏览位置，以免每次打开都掉进同一本书
48. 作为漫画读者，「上次停留的位置」要恢复退出时的**目录层级**（排序方式与方向属于全局设置、本就一直保持，不参与恢复；也不恢复滚动位置），以便继续整理/浏览
49. 作为漫画读者，我想有一个首页展示来源/连接列表，以便从零开始选择去处（首页只放来源入口，不放设置——设置只由导航抽屉到达）

### 设置与周边

50. 作为漫画读者，我想设置页面旋转：竖屏 / 横屏 / 跟随系统（默认跟随），以便适配设备与阅读姿势
51. 作为漫画读者，我想主题深色/浅色跟随系统、也可手动覆盖，以便夜间舒适
52. 作为漫画读者，我想条漫模式背景为纯黑（OLED），以便省电护眼
53. 作为漫画读者，我想通过左侧滑出的导航抽屉（仅左侧）进入 首页 / 阅读器 / 书柜 / 设置 四个入口，以便与 Perfect Viewer 的结构一致
54. 作为漫画读者，我想支持 jpg/jpeg、png、webp、gif（静态显示首帧）以及 CBZ/ZIP 压缩包与图片文件夹（ZIP 内部图片也按名称自然排序），以便覆盖我的全部库存

## Implementation Decisions

- **技术栈**：Kotlin + Jetpack Compose，minSdk 26（Android 8.0），侧载分发（SAF 而非全盘存储权限与商店审核策略一致）
- **Source 统一接口**（核心架构 seam）：四种来源各实现一个适配器，接口能力=列出条目（含排序参数）、打开书（取得页清单）、按页取图、进度读写；来源差异全部压在适配器内；**空书口径（票 #97，四来源一致）**：书存在但一页都没有（压缩包内没有图片、Komga 返回空页列表）时返回 `pageCount == 0` 的句柄，界面给中文空态（`ReaderScreen` 的「此书没有可显示的页面」）——本地与 Komga 同口径；抛 `IllegalArgumentException` 只留给「不是一本书」的输入（id 形状/前缀不对、越界引用、目录本层没有图片）
- **名称自然排序比较器**：独立纯函数模块，复刻 Windows 资源管理器逻辑比较（符号<数字<字母<假名<汉字、数字按数值、不分大小写、假名按五十音序、汉字按拼音），用于文件目录、CBZ 内部、相邻书判定；**已知限制（票 #83）——实测口径，不只是表外字**：汉字段用 JDK 的中文 Collator，其**汉字字表与 Windows NLS 字表逐字不同**，GB2312 表内字同样可能中招（kòu 音的常用表内字被排到「最」「自」之后；表外字如 仮/帰/話/結/絶/親/隣/現/準/優/悪/節/謎/酔 被整块排到汉字末尾）；另有三个次级根因：**假名段与汉字段的段边界**（本实现按 run 切分比较，Windows 按逐字符类优先级，公共前缀相同而边界后一类不同时结论相反）、**假名浊音**（JDK 日语 Collator 在 primary 层把 こ/ご 同权，同音浊音段被当成前缀而排到清音之前；Windows 是 こ < ご）、**符号段内的空白**（本实现把空白与「空白+符号」当同段字典序比较，Windows 视空白可忽略、由后面的字符定胜负）；差多少：维护者本机**某次本地实测**（145 条真实目录名样本，2026-09-19）位次不一致 96 条、反序对 556 对——这是一次快照，不是恒定的产品事实，**权威数值以本地探针输出为准**（探针见 Testing Decisions「Seam ②」），样本文件或比较器一变即需重新标定；本项口径与授权来源见 **#83 评论**（该票 AC4 按「未达成」记录，四类根因均授权登记）；追平需自造汉字权重表并重做假名段规则，另行开票
- **文件源访问**：SMB 用成熟开源 SMB 客户端库（smbj / jcifs-ng 择一，实现期以随机访问性能定夺）；WebDAV 走 HTTP（PROPFIND 列目录 + Range 取数据）；本地走 SAF
- **CBZ/ZIP 读取**：解析中央目录 + 随机访问（seek），支撑按页取图与页面预览，不必整包下载
- **Komga 集成**：REST——`POST /api/v1/series/list`、`POST /api/v1/books/list`（`sort=metadata.releaseDate`；书列表的筛选走请求体的条件 DSL，如按系列 `{"condition":{"seriesId":{"operator":"is","value":"<uuid>"}}}`，形状依据上游 tag 1.26.3 的 `domain/model/BookSearch.kt`（`condition: SearchCondition.Book?`）、`SearchCondition.kt` 的 `SeriesId(@JsonProperty("seriesId") …)` 与 `SearchOperator.kt` 的 `Equality`（判别属性 `operator`，`@JsonTypeName("is")` → `Is(value)`）；查询串只认 `page`/`size`/`sort`，旧的 `series_id=` 与顶层 `seriesId` 都会被服务器静默忽略而返回全库的书——票 #77 真机 v1.26.3 已复现）、按页取图 API、`PATCH /api/v1/books/{bookId}/read-progress` 进度双向同步
- **持久化**：Room 数据库——连接配置（**凭据加密存储**：SMB/WebDAV 的密码、Komga 的 API Key/密码经 Android Keystore 的 AES-256-GCM 加密后落库，形如 `enc:v1:<Base64(IV‖密文+tag)>`；密钥为 app 级不可导出条目，不硬编码、不随包分发；v4→v5 迁移把存量明文改写为密文，读路径仍认旧明文，解密失败提示重新填写——票 #27）、阅读进度、浏览历史、最近阅读
- **图片解码**：支持 jpg/jpeg、png、webp、gif（首帧静态）；大图子采样/分块解码防 OOM

- **列表条目呈现与页数（票 #36）**：浏览列表行内只有封面 + 名称（长名称最多两行），不再有「文件夹 / 书 · N 页」副标题；已读书目的进度条在**名称正下方、与名称左缘对齐**（名称那一列内、位于封面右侧，**条右端到名称列右缘（即行内容右缘），不做内缩**；票 #92 需求 2；网格档则是**压在封面下缘、不占布局**），未读的书两档都不画、因此不留空白；条样式两档一致（票 #92 需求 3）：轨道 = **主题 `onSurface` 的 30% 不透明度**（跟随深浅主题；**有意可透出底图**）、**方头**端帽（无圆角）、高 **6dp**、不画 stop indicator；**网格档**的条下另铺一层**黑 45% 暗底**（票 #92 需求 5 方案 A：与条同宽同高、叠在封面下缘、不占布局——压在浅色/白色封面上时轨道才看得清；**列表档没有**这层；未读时暗底与条都不画）；文件源（本地/SAF、SMB、WebDAV）枚举期**不为页数**读压缩包中央目录、也不为页数列子目录（为封面解出包内首页的读取已随票 #30 一并移到按需封面通路），列表条目的页数一律为空，页数只在打开书后由 `BookHandle` 给出（阅读器菜单「当前页 / 总页数」据此）；Komga 的页数来自服务器返回的 payload（零额外成本、进度同步需要它）照常返回，但界面不显示
- **SMB 连接表单（票 #38）**：字段收成「服务器地址（可含端口，如 `192.168.1.10:1445`；不写即 445）+ 路径（`共享名/子目录`，子目录可省）」+ 用户名/密码/域；地址容忍 `smb://` 前缀（含前缀之后的空白）、前后空白与首尾斜杠/反斜杠，路径容忍前后空白、`/` 与 `\` 混用、前导/尾随/重复斜杠与 `.` 段，规范化后第一段即共享名（含 `..` 直接拒绝）；IPv6 字面量按标准写成 `[fe80::1]:1445`（方括号内即主机，其后只允许 `:端口`；存量里带或不带方括号都能解析），只有一个冒号的串按 `主机:端口` 拆、含多个冒号的裸串整串当主机（裸串最后一个冒号后的数字与地址分不开），非数字或越界提示「端口必须在 1–65535 之间」，空地址/空路径各有中文提示；**存储形状不变**——仍落 host / port / share / rootPath 四个逻辑量（Room 无需迁移），老配置编辑时「共享名 + 起始目录」回填成一条路径、非默认端口折进地址；连接列表展示名 `共享名 @ 服务器地址`（非默认端口带 `:端口`；存量连接 Room 里的 displayName 列不重算，下次编辑保存后生效）；节点 id 前缀仍按非默认端口区分（不加 IPv6 方括号——id 前缀是进度键的一部分，改写法会让既有进度键失效）
- **排序在展示层翻转（票 #29）**：来源接口只接受排序方式、不接受方向（`Source.listEntries` 契约不变，Komga 的服务端 sort 串按其既有方式）；方向由界面按全局排序设置对来源返回的已排序结果**整份翻转**后展示，四个来源行为因此一致。全局排序设置（排序方式 + 名称/修改时间/发布时间三个类别各自的方向，默认方向=现状）落 SharedPreferences（`ui/SortSettingStore.kt`）；票 #49 起条目列表只剩浏览页一处（书柜入口列表放的是连接、不放排序），因此它是浏览页的排序来源；「上次停留的位置」只记目录层级，切排序不改写它；**排序设置变化时浏览页两档滚动回到顶部（票 #58）**：复位只由排序设置变化触发（切换排序类别、或点当前类别反向），列表档与网格档各持一份滚动状态、各自复位；换排序类别会重新枚举（异步），新顺序落地那一帧会再复位一次，因此任何一次重排都不会带着旧锚点把视口带走；非排序变化不触发复位（下拉更新重列、切视图档位、进子目录/返回上级、从阅读器返回都照旧保持原位置，滚动位置本身仍属 Out of Scope）
- **启动中转与退化（票 #26）**：启动判定（读设置项与上次状态 + 按 id 取连接 + 建来源会话）期间停在中转页——该页显示进度指示、**不响应抽屉边缘手势**（判定未完成时划出抽屉，「书柜/设置」会被判定完成后的一次性 `popUpTo` 吞掉、「阅读器」只会提示「请先选择一个来源」）；**启动判定所需的落盘状态**（启动页面设置、`StartupStore`）在启动 effect 内、第一次挂起之前同步读完（不占用组合期；且写点已限定在离开中转页的路由上——`readingFlagToRecord`，因此本会话的写不会污染启动期的读）；**本项只覆盖启动判定本身（`AppNav` 的启动 effect），其余界面各自的设置读不在本口径内**（票 26 第 6 项的收窄：`BrowserScreen`/`BookshelfScreen` 的组合期排序设置读、`SettingsScreen` 的设置初值、`ReaderScreen` 的模式/方向读、`MainActivity` 的主题/旋转读都照旧——它们读的 prefs 在 `MainActivity.onCreate` 已加载、后续是内存读，改动会牵动首帧呈现，已登记 #25）；落地导航只做一次，但**还原后栈顶仍是中转页时补跑一次**（慢来源冷启动期间旋转、进程被杀后回到前台；否则该页没有任何出口）；启动目标指向的连接已不存在时：浏览目标回落首页并**清掉** `StartupStore` 里那条不可用的「上次停留的位置」（读库本身失败时不清：那是暂时性故障，不等于连接被删），阅读器目标先退化为上次停留的位置、仍不可解析才回落首页；判定/建会话/导航抛预期外异常时**降级只落首页**（取消照常传播，不在取消后导航；该降级可能再压一层首页）
- **会话来源的复用与释放（票 #26）**：启动覆盖会话来源沿用票 #30 的单槽复用与已定释放路径——同一 connId 复用现实例，换到别的连接 / 连接被编辑或被删除 / App 退出三条路径都会释放旧实例，且释放一律在后台进行（不阻塞导航）；因此进程存活时重建 Activity 不会留下上一会话的 SMB 会话
- **UI 骨架**：浏览页（票 #53 起的顶栏是**「视图」菜单 + 排序**：视图档位 = 列表 / 网格 2 列 / 网格 3 列 / 网格 4 列，默认网格 2 列，非法或缺失值回落网格 2 列，全 app 一份、跨目录层级与连接与重启保持；手动刷新是**下拉更新**——只认拖拽、滚轮不触发；条目形态随档位切换，两档共用枚举/方向/名称/进度/点击语义）、阅读器（类型 3 触摸区域、菜单 overlay、网格页面预览、上一本/下一本）、导航抽屉（左缘、首页/阅读器/书柜/设置；浏览历史的后退/前进只在系统返回手势与鼠标侧键，票 #32 起不再有抽屉入口）——**返回逐级（票 #70）**：抽屉的首页/书柜/设置三个顶层入口收掉根首页之上的一切层级（含浏览层）后落在根首页之下（`launchSingleTop` 不叠加、不形成环），浏览历史是回退栈里浏览层的**镜像**：随 Activity 销毁而清空（`closeSession`）、在启动落地时**重置**为本次创建的浏览层（回退栈只有一层时 `canGoBack` 不为真），因此浏览页的返回处理器只在真的还有上一层时接管（默认关闭的导航观测点 `nav startup ...`/`nav browseBack ...` 给出回退栈深度 + 栈顶路由 + 历史游标，见 `PerfTiming`）、设置页（阅读模式、旋转三选一、双击倍率、启动页面五选项、始终从第一页打开、音量键、主题）；**窗口全幅绘制（票 #44）**：窗口进入 edge-to-edge 并允许在挖孔/刘海区绘制（`LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES`），阅读器画面铺满到屏幕顶端与挖孔侧；列表类界面继续由 Scaffold + 顶栏消费系统栏 inset（不双重内缩），贴底浮层（阅读菜单面板、跨书确认条）显式消费系统栏与挖孔 inset；系统栏图标明暗跟随深浅主题；**条目名称断行（票 #47）**：名称按「能塞就塞」断行（最多两行、不省略号），在 `]`、`-` 这类闭合/连接标点之后与数字字母交界处补零宽空格作额外断点（**票 #92 起**：长度 ≥ 4 的 **ASCII 字母/数字串**在串内每 2 个字符也补一个断点，长词因此可就地断开、把行尾填满——维护者选定「允许长词内断、不引入连字符」，阈值取 4 是为了盖住维护者那本书里 6 字符的英文词；3 字符以下与其它文字（西里尔/阿拉伯/天城文等）保持原子），并给名称文本指定贪心断行配置（API 33+ 生效）；**名称块高度（票 #94）**：网格档的名称块**固定两行高**（`minLines` = 行数上限 = 2）——1 行名也占满两行，短名称下方的留白就是第二行的行高（非硬编码像素），同一排格子因此等高、格底逐行对齐；列表档不固定（最小行数 1），行高随名称 1/2 行变化是既有行为（票 #94 不动列表档）；**启动图标（票 #37 / #43 / #55）**：三层自适应图标（白底 `#FFFFFF` + 深蓝环 `#0D47A1` + Roboto Bold「CV」字标 `#111111`），环外径 52.7/108（48.8%、描边 5.0%，与 Mihon 的比例接近）、字标 ink 宽 28/108（25.9%）

## Testing Decisions

- **只测外部行为，不测实现细节**：测试通过公共接口断言可观察结果
- **Seam ①（主）：Source 统一接口**——四种实现跑同一套行为测试集（浏览条目→排序→打开书→按页取图→进度读写）：本地=临时目录 fixture（纯 JVM）、WebDAV=容器化服务、SMB=容器化 Samba、Komga=容器化真实实例（兼验 REST 契约与进度同步）
- **Seam ②（辅）：名称自然排序比较器**——纯函数测试，入库黄金样本一律用**合成名**（仓库是 PUBLIC，真实书库名不进仓库），守护 Windows 兼容硬约束：`第2话`<`第10话`、符号/数字/字母/假名优先级、大小写、假名五十音序、中文拼音、GB2312 表外字归汉字段；**真实书库顺序由本地探针** `WindowsNameOrderLocalProbeTest` 读 `references/name-order-expected.txt`（不入库）逐条比对，给出差异表并按「位次不一致/反序对」棘轮基线报警（基线常量及其重标要求写在测试里）；文件不存在（干净检出）时**数据类测试 skipped**，表外字分类口径自检不读文件、照常跑
- **绿地无先例**：以上两个 seam 即测试基线的起点，后续功能测试优先复用这两个口
- **UI 层**：Compose 交互不做大规模自动化，走手动验收清单（触摸区域、缩放、鼠标事件、预览）

## Out of Scope

- CBR/RAR、PDF、bmp、avif、heic/jxl 格式支持
- 压缩包内部按目录分卷阅读（CBZ 内的图片仍按 `isArchiveImageEntry` 全深度收集，票 #97）
- 双页拼页模式
- 阅读菜单内的返回按钮、模式切换、设置入口（返回=全面屏手势/鼠标后退侧键；模式切换与设置在设置页/抽屉）
- **OPDS（1.x 与 2.x 全不做，含下载缓存与流式阅读）**
- 前进侧键回到阅读器
- 书柜跨来源混排视图
- **逐本收藏/入柜**（书柜只按连接陈列根条目）
- 浏览滚动位置的恢复
- 流式列表（条目先出、`isBook` 后到；名称与点击已不被封面阻塞，但列表仍在整批属性探测完成后一次返回）
- 音量键以外的键盘快捷键体系、手柄支持
- 谷歌商店分发与审核合规
- 搜索/全文检索功能
