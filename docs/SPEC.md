## Problem Statement

我在 Windows 上把漫画库整理好（目录命名、排序都符合 Windows 资源管理器规则），
再 rsync 到 Linux NAS。

在安卓设备上至今没有一款完全符合我使用习惯的漫画阅读器：

- 浏览 NAS（SMB/WebDAV）、连 Komga、条漫阅读、蓝牙鼠标操作、精确到页的跳转预览、
  与 Windows 一致的排序——这些散落在不同 APP 里，或行为对不上
  （尤其是排序规则与封面/进度呈现）
- Perfect Viewer 最接近但闭源且若干交互不可定制

## Solution

Comic-Viewer：一款按我的习惯定制的安卓原生漫画阅读器。

- **四来源统一浏览**：本地存储（SAF）、SMB、WebDAV、Komga，同一套浏览/排序/阅读体验
- **两种阅读模式**：条漫（垂直连续滚动）与单页（LTR/RTL）
- **蓝牙鼠标全支持**：滚轮滚动/翻页、左右键、后退/前进侧键
- **Windows 一致的名称自然排序**与全来源通用的时间排序（修改时间/发布时间）
- **Perfect Viewer 风格交互**：触摸区域类型 3（纵向三等分）、双击放大、
  跳页横向预览条（全书页滑动）、上一本/下一本
- **进度管理**：本地持久化 + Komga 双向同步；
  列表进度条（绿 = 进行中、红满格 = 读完）
- **书柜按连接分柜**，陈列每个连接的根条目，封面自动取首页图（细节见故事 43/44）；
  没有逐本「加入书柜」的动作

技术底座：Kotlin + Jetpack Compose，minSdk 26。

### 来源与连接

1. 作为漫画读者，我想添加 SMB 连接（服务器地址可含端口、路径 = 共享名/子目录、用户名/密码），
   以便浏览 NAS 上的漫画库
2. 作为漫画读者，我想添加 WebDAV 连接（URL、凭据），以便浏览支持 WebDAV 的网盘/NAS
3. 作为漫画读者，我想添加 Komga 连接（服务器地址 + 凭据），以便浏览我的 Komga 服务器
5. 作为漫画读者，我想通过系统文件夹选择器（SAF）授权本地文件夹，
   以便阅读手机/平板内的漫画而不必授予全盘权限
6. 作为漫画读者，我想在同一来源下建立多个连接，以便同时访问多台 NAS/多个账号
7. 作为漫画读者，我想编辑和删除已有连接，以便维护我的来源列表
8. 作为漫画读者，当连接失败时我想看到明确的错误原因（地址不通/认证失败/超时），
   以便自行修正

### 浏览与排序

9. 作为漫画读者，我想在浏览列表看到每个条目的封面，以便一眼认出漫画
   - 书取其第一页
   - **容器取其本层首图**
   - 多子文件夹的文件夹逐级下取（每一层按同一套优先级：本层图 → 本层首个压缩包的首帧）
10. 作为漫画读者，我想按名称自然排序浏览，以便 APP 里的顺序和我电脑上整理的完全一致
    - 规则与 Windows 资源管理器一致
    - 特殊字符先于数字、数字先于字母、假名先于汉字
    - 数字按数值比较（第2话 < 第10话）
    - 字母不区分大小写
    - 假名按五十音序（平假名与片假名同权）
    - 汉字按拼音
11. 作为漫画读者，我想按修改时间排序（文件 mtime），以便定位最近更新过的内容
12. 作为漫画读者，我想按发布时间排序（书的发布日期，来自 CBZ 内 ComicInfo.xml 的
    Year/Month/Day），以便按出版顺序阅读
13. 作为漫画读者，当书没有发布日期元数据时（如图片文件夹），发布时间排序应回退为修改时间排序，
    以便排序始终可用
14. 作为漫画读者，我要求全部四种来源都支持名称/修改时间/发布时间三种排序，以便体验一致
    - Komga 的发布时间排序走服务器端 sort，修改时间用服务器记录的文件修改时间
    - **排序方式与方向是全局一份设置**
      - 三种排序各自带方向（默认：名称升序、时间类新→旧）
      - **排序菜单给恰好 6 个显式选项（类别 × 方向）**
      - 点一项即类别与方向同时生效（不再有「点当前类别再点一次即反向」）
      - 当前生效项打勾、按钮文字写当前类别与方向
      - 选定后跨目录层级、跨连接、跨重启保持，浏览列表与书柜柜内读写同一份
    - **例外**：Komga 的「阅读过」入口固定按最近阅读倒序，见故事 15
15. 作为漫画读者，我想在 Komga 来源按
    **四个入口（收藏 / 系列 / 书籍 / 阅读过）→ 收藏或系列 → 书** 的结构浏览，
    以便符合 Komga 的组织方式
    - 起始层由连接表单的「路径」决定，逐级返回一路回到路径起点
    - **有意例外**：「阅读过」固定按最近阅读倒序，不跟随排序菜单的类别档
16. 作为漫画读者，我想在浏览列表看到已读书目名称正下方的进度条，以便了解之前读到哪里
    - 在名称那一列内、与名称左缘对齐；网格档则是压在封面下缘
    - 部分填充绿色 = 进行中，满格红色 = 读完
17. 作为漫画读者，在混合目录（既有图片又有子文件夹）中我想点击图片条目后从该图开始
    按自然排序连读本目录图片，以便灵活入书
    - 混合目录因此是**容器**：点它先进浏览列表
18. 作为漫画读者，在混合目录中我想点击含图片的子文件夹后按顺序阅读它，
    以便直接进入那一话
    - 只含图片的子文件夹才是书，在列表里直接打开
19. 作为漫画读者，我想在浏览层级间前进/后退，以便快速往返于层级 A/B 之间
    - 全面屏返回手势与鼠标后退侧键 = 后退
    - 前进侧键 = 前进
22. 作为漫画读者，我想用鼠标滚轮在 APP 的各个列表界面滚动，以便不碰屏幕也能浏览

### 阅读器

23. 作为漫画读者，我想用条漫模式阅读（垂直连续滚动，可按页跳转：跳到下一页/上一页页首），
    以便看 webtoon 类作品
24. 作为漫画读者，我想用单页模式阅读并选择左→右或右→左（RTL）方向，以便看日漫扫描本
25. 作为漫画读者，我想在设置里切换阅读模式（菜单里不放切换入口），以便阅读期间不被误触
26. 作为漫画读者，我想让触摸区域按类型 3 划分，以便肌肉记忆一致
    - 屏幕纵向三等分，且两种模式、两个单页方向下规则完全统一
      （左区恒为上一页、右区恒为下一页，不随 RTL 镜像）
    - 左区 = 上一页（条漫 = 上一张图）
    - 中区 = 呼出菜单
    - 右区 = 下一页（条漫 = 下一张图）
27. 作为漫画读者，在第一页点左区、最后一页点右区触发上/下一本时，我想先在底部弹出确认条，
    点击该按钮才真正跳转，以便杜绝误触跳书
    - 整宽条、三等分三列
    - 中格 = 当前位置（如「第一页」）
    - 按钮格按方向取左/右一格 = 橙色跳转按钮（如「上一本书」）
      —— 首页方向在左格、末页方向在右格
    - 按钮格与触摸区列逐像素对齐、整格可点
    - 中格与另一侧空白格不做任何动作
    - 而阅读菜单底部的上一本/下一本按钮则直接执行、无需确认，以便明确意图时一步到位
28. 作为漫画读者，我要求相邻书的判定只由名称自然排序决定，以便上一本/下一本顺序可预期
    且到头有明确反馈
    - 与当前列表排序方式及方向都无关
    - 范围 = 同一目录（文件源）或同一系列（Komga）
    - 已到头时点击不置灰，而是弹提示「无上一本」/「无下一本」
      （该层本会话还没被列过时同一条提示——邻位未知期与「确实到头」表现相同）
    - 进入阅读器后**后台**补齐该层，补齐后邻位恢复
29. 作为漫画读者，我想点击屏幕中区呼出阅读菜单，以便界面干净且不打断阅读
    - 面板贴屏幕底部、半透明（不铺满全屏深色遮罩，当前页仍可见）
    - 含书名标题、跳页滑动条、当前页/总页数、上一本/下一本按钮
      （无返回按钮、无模式切换、无设置入口）
    - 书名标题与页码字号随面板内宽放大
      （标题 = 内宽 × 0.05 夹 18–24sp、页码 = 内宽 × 0.05 夹 16–24sp）
    - 标题紧贴面板顶部（上方留白 3dp）
    - 长书名**最多 3 行**（动态 1→3 行，行数变化只抬高面板、**不压缩预览条**）
    - 断行口径与浏览页条目名一致
    - 当前页/总页数与上一本/下一本在**同一行**、**三等分三列**
      （上一本在左 1/6 处、页数在正中 1/2、下一本在右 5/6 处，每列内容在自己列内居中；
      票 #105 r9）
    - 底部行**可见高 36dp**，命中带 48dp（**只向下挂**、不向上侵占滑条行；票 #105 r10）
30. 作为漫画读者，我想在打开阅读菜单时即看到全书页的横向预览条
    （滑动式、每格带页码、当前页高亮），以便不必先拖动就能看清附近几页
    - 拖动滑动条时预览跟随目标页、松手后回到当前页
    - 单击滑动条轨道与拖动等价——预览以该位置对应页为中心、随即跳到该页
    - 点击任意预览缩略图直接跳到该页、**菜单保持打开**，与滑动条跳页同一条落地路径
    - 跳页后**当前页缩略图落在预览区正中**，首页与末页除外——到头只能贴边（票 #105 r13）
    - 条漫模式的「当前页」= 顶部可见页；已滚到书末且内容超过一屏时报最后一页
31. 作为漫画读者，我想双击放大，以便看清细节
    - 以双击位置为中心，倍率默认 2.0x、可设 1.5x–4.0x
    - 放大是约 240ms 的缓入缓出过渡、缩放与位移一起走完
    - **缩放后不窄于视口的那条轴**上双击点整段过渡不动
    - 页窄于视口的轴（单页模式横屏几乎必中）偏移由既有钳制公式决定、过渡中途可见漂移
    - 双指缩放与放大后单指平移仍是逐帧跟手，动画让位于手指
32. 作为漫画读者，我要求放大状态按页记忆，以便长篇细读时不用反复放大
    - 翻页/回翻不复位，仅再次双击恢复适屏（复位同样平滑过渡回 1.0）
    - 动画进行中再次双击/翻页以最新状态为准，不回跳、不错位
    - 且退出阅读器后放大状态丢弃（重开漫画看到原样）
33. 作为漫画读者，我想双指开合缩放（1x–8x、力度随手势），以便自由控制缩放
34. 作为漫画读者，放大后我想单指拖动平移
    （条漫 = 水平平移 + 垂直继续滚动；单页 = 限制在图片边界内），以便查看局部
35. 作为漫画读者，我想用蓝牙鼠标滚轮在阅读器内滚动页面（单页模式一格 = 翻一页），
    以便解放左手
36. 作为漫画读者，我想让鼠标左键等同触摸区域行为、右键与左键一致，
    以便只用鼠标也能完成全部阅读操作
37. 作为漫画读者，我想让鼠标后退侧键 = 浏览历史后退、前进侧键 = 浏览历史前进
    （前进不回到阅读器），以便导航符合系统习惯
38. 作为漫画读者，我想让 APP 适配全面屏返回手势（阅读器内不做返回按钮），
    以便符合现代安卓习惯
39. 作为漫画读者，我想用音量键翻页，以便单手阅读
    - 单页 = 翻一页；条漫 = 跳到下一页/上一页的**页首**

    - 到书首/书末不交还系统，而是就地弹出**跨书上/下一本确认**，

## Implementation Decisions

### 技术栈

Kotlin + Jetpack Compose，minSdk 26（Android 8.0），
侧载分发（SAF 而非全盘存储权限与商店审核策略一致）

### Source 统一接口（核心架构 seam）

- 四种来源各实现一个适配器
- 接口能力 = 列出条目（含排序参数）、打开书（取得页清单）、按页取图、进度读写
- 来源差异全部压在适配器内

**空书口径（四来源一致）**：

- 书存在但一页都没有（压缩包内没有图片、Komga 返回空页列表）时
  返回 `pageCount == 0` 的句柄，界面给中文空态
- 抛 `IllegalArgumentException` 只留给「不是一本书」的输入
  （id 形状/前缀不对、越界引用、目录本层没有图片）

### 名称自然排序比较器

独立纯函数模块，用于文件目录、CBZ 内部、相邻书判定
（**比较规则见故事 10**；本段只记限制、探针与已知偏差）。

**已知限制**：以下各条只登记、不追平。

- 汉字段用 JDK 的中文 Collator，其字表与 Windows NLS **逐字不同**
  - GB2312 表内字同样可能中招、表外字被整块排到汉字末尾
- 另有三个次级根因：
  - **假名段与汉字段的段边界**（本实现按 run 切分，Windows 按逐字符类优先级）
  - **假名浊音**（JDK 日语 Collator 在 primary 层把 こ/ご 同权，Windows 是 こ < ご）
  - **符号段内的空白**（本实现当同段字典序比较，Windows 视空白可忽略）
- 差异幅度以本地探针输出为准
  （`WindowsNameOrderLocalProbeTest` 读 `references/name-order-expected.txt`，
  样本或比较器一变即需重新标定），不写死数字
- 追平需自造汉字权重表并重做假名段规则，另行开票

### Komga 集成

REST 接口：

- 按页取图 API
- 进度双向同步：`PATCH /api/v1/books/{bookId}/read-progress`

**书列表筛选走请求体的条件 DSL**：

- 形状：按系列 `{"condition":{"seriesId":{"operator":"is","value":"<uuid>"}}}`
- 依据：上游 tag 1.26.3 的 `BookSearch.kt` / `SearchCondition.kt` / `SearchOperator.kt`
- 查询串只认 `page`/`size`/`sort`
- **`series_id=` 与顶层 `seriesId` 会被服务器静默忽略**，返回全库的书

**根层四入口**：

- `GET /api/v1/collections`（收藏列表）
- `GET /api/v1/collections/{id}/series`（收藏内容）
  - 该端点两种响应形状都认：Spring Data 分页对象与纯数组
  - **按服务端返回什么就渲染什么**：带 `media`/`seriesId` 的条目渲染为书行、其余为系列行

**起始浏览路径**（落 `browsePath` 键，与 baseUrl 里的 URL 子路径不同义）：

- 取值 `/`、`/collections[/<id>]`、`/series[/<id>]`、`/books`、`/read`，
  决定 `listEntries(null)` 落到哪一层
- 非法/缺失一律回落 `/`
- 段名是**稳定 token**（不随界面文案变）；解析**兼容首轮落过的中文段**
- 「阅读过」固定按最近阅读倒序（故事 14/15 的例外）

**id 形状**：

- 书 id：`.../series/<seriesId>/book/<bookId>`，存量进度键不变
- **没有 `seriesId` 的书**用 `.../book/<bookId>` 单独表达（能列出、能进入、能记进度）
- 分类/收藏容器用独立命名空间：`.../cat/<kind>`、`.../collection/<id>`

#### 分页取数上限（票 #119）

- 浏览各层都走服务端 `page`/`size`
- **20 页 = 1 万条这条上限只作用在「一次取完整层」的路径上**
  （反向档与回退默认实现的层，每页 500 条）
- 取满 20 页而服务器仍说「还有下一页」时**不再静默截断**：
  浏览页在列表上方显示一条可见提示
  「只显示了前 N 条（已达到 20 页取数上限，之后的条目未显示）」（N = 本次已取条目数）
- 未撞上限不给提示
- 排序口径与书条目 id 形态（存量进度键）不因这条提示改变

#### 路径选择器按需加载（票 #119 步骤 2）

- 候选列表收 `page`（从 0 起）、每次只取服务端一页（500 条），**滚到底再取下一页**
  —— 打开大库（8600 本）不再先拉全量 JSON + 建全表
- 根层四项是本地常量、一页给完
- 某页的条目全被过滤（收藏内容里的书不是可下钻的层）时自动往后取，不卡在「加载中…」
  - **连跳空页有 20 页上限**：跳满 20 页仍没有可下钻的层即当终止，不再往后取
- 后续页失败不清空已取到的候选（提示留在列表上方）
- 选择器不一次取完，因此**没有截断提示**；「一次取完整层」那条路径的 20 页上限不作用于它

#### 浏览列表按需加载（票 #119 步骤 3）

**首帧**：

- 浏览页**正向档**首屏先落已有快照当首帧（`Source.snapshotEntries`，0 请求）
- 两条路：
  - 文件源 = **落盘的列表快照**（见「列表快照落盘」）
  - Komga = **会话内列表**：内存一份、不落盘、不含 mtime，
    **不是**词表里的「列表快照」（词表那条含该目录自身 mtime 与落盘，
    见 `CONTEXT.md`；票 #123）
- 随后按这一帧的长度与**恢复到的滚动索引**中的较大者为下限**连续取够页再替换它**
  - 因此返回浏览页时列表不少于原位置所需长度
  - 取到的页里出现空页即当终止，不再往后取
- 滚到列表尾部再取下一页；服务器排序即最终顺序的层可一直滚到底（不受 1 万条上限截断）

**列表快照只当首帧**：

- 快照**整份上屏**，**不是第二个数据来源**
- 它只与「恢复到的滚动索引」一起决定首屏要取够多少条
- 取数只有 `Source.listEntriesPage` 这一条路

**逐页与整层必须同序**：

- `Source.listEntriesPage(containerId, sort, page, size)` 逐页拼起来的结果
  与 `listEntries` 在**同一 (containerId, sort)** 下逐字同序
- 默认实现 = 全量后切片（文件源没有服务端分页）
- Komga 只在「服务器排序即最终顺序」的档位按页直取服务器：
  修改时间 / 发布时间 / 「阅读过」全天 / 某系列的书的那两档
- 名称档与收藏/系列列表回退默认实现
  （要按 Windows 名称序本地重排，逐页直取会打乱全局顺序）
- **回退档的整层枚举在一次浏览会话内只做一次**
  （结果进会话快照，后续页从它切片，下拉更新才重枚举）
- 因此名称档（默认排序）仍整层取数、受 1 万条上限并给提示
- **Komga 的名称档首帧不允许空白等整层**只对「会话内已枚举过这一层」成立
  （先落会话内列表那一帧，票 #123）
- **冷启动**（进程重启后首次进这一层、会话内没有快照）仍要等整层枚举；
  消解需给 Komga 落盘列表快照（新机制，票 #123 未做）

**起始路径（`browsePath`）**：

- 落在上述任一层的连接（`/read`、「书籍」、「某系列」）走同一套判据
- 能直取的照样直取：`/read` **不分排序档**都直取（与上文「阅读过全天」同一档）
- `/books` 与 `/series/<id>` 只在非名称档直取，**名称档照旧整层取**
  （要按 Windows 名称序本地重排，票 #123）

**直取档的取数下限（票 #124）**：

- **直取档的会话内列表只含第 0 页**（票 #119 定的「快照只缓存首屏」约束不变）
  ⇒ 这一帧可能短于离开前
- **取数下限 = 「快照长度」与「恢复到的滚动索引 + 1」中的较大者**
- 两档的 `firstVisibleItemIndex` 都是 `Lazy` **项坐标**
  （条目 + 截断提示行 + 尾部触发件行）
  - 网格档给的是首个可见**行的首个格子**、行号 = 项索引 ÷ 列数，界面不做换算
- 从这个下限连续取够页再替换 ⇒ 上文「列表不少于原位置所需长度」对直取档同样成立
- 续页照旧靠滚到底
- 恢复索引是**下限不是请求数**：来源说没有下一页（或出现空页）即停，请求数仍有界

**正向档取够之后还要把位置放回去**：

- 反向档是整份取完再翻转、不做显式放回（见段末）
- 返回时首帧那份短列表已让 `Lazy` 把恢复的索引夹到已加载末尾
  （票 #124 r2 实测：恢复到 600、首帧 200 条 ⇒ 索引落到 184）
- 列表涨长不会自己回去 ⇒ 取够页后界面**显式滚回恢复索引**
  - 当前位置已经不小于它、或这一层没那么长时不动
  - **下拉更新与重试后按当下位置重算**，否则在顶部刷新会被拽回上次恢复的位置

**代价（票 #124 登记）**：

- 直取档的**整层枚举不再写这份会话内列表**
  （同一 (容器, 排序) 上，整层枚举与第 0 页共键而长度差一个数量级，
  写进去会让方向切回正向时首屏按整层长度取页、发 ⌈N/每页⌉ 次请求）
- 因此**反向档**在直取层上从阅读器返回、**且该键还没被第 0 页写过时没有会话内首帧**：
  先显示「加载中…」，等这次整层枚举跑完才上屏
  - 反向档每次进入本来就要整份取完再翻转，请求数不因此增加
  - 该键被正向第 0 页写过时仍给出一帧，只是长度 = 第 0 页
- 正向档不受影响（第 0 页帧照旧）
- 这一条也是「同步快照访问器」那节「从阅读器返回浏览页时列表立即可见」的适用范围限定
- 让两种档各有各的键需要把方向带进 `Source` 的会话列表接缝
  （方向现属展示层概念），留作新决策

**反向档仍是整份取完再翻转**（按需加载只对正向档成立）：

- 方向是展示层概念、施加在整份列表上（见「排序在展示层翻转」）
- 追加页只能往尾部接，复现不了「从尾到头」

### 阅读页缓存

**页字节磁盘缓存**（`PageDiskCache`）：

- 键 = 书 id + 页索引的 SHA-256 前 32 位十六进制，上限 200MB
- **最终一致**：达到上限时清理在后台分批进行，写入后可短暂高于上限
  - 超上限按修改时间从旧到新淘汰到上限的 80%
- 写入按「先写 `.tmp` 再改名」原子落盘（0 长度残留视为未命中）

**清理不在取页路径上**：

- 写入只累加一个字节计数并把清理排到后台单线程执行器
  - 一趟最多删 `PAGE_CACHE_TRIM_BATCH` 个文件
  - 还没到目标线**且本趟确有文件被删**才再排一趟
  - 一个都没删掉就停到下次写入
- 因此「取一页要多久」与缓存目录里有多少文件无关
- 本进程内第一次写入会排一趟清理、由那趟先核一次目录真实占用
  （目录跨进程存在，计数不然会偏低）

**内存层是两份独立预算的位图缓存**（按屏宽解码、RGB_565）：

- **页面位图 = max(4MB, 堆 1/8)**
- **封面位图 = max(4MB, 堆 1/16)**
- **互不淘汰**——票 #108 r5 起
  - 此前两者共用一份按堆 1/8 的 LruCache，阅读器一页几十 MB 会把封面整批淘汰
- 命中即不再取字节

### 书与容器

**书的判定**：

- 一个目录**本层只有图片**才是书（打开 = 按名称自然序读本层全部图片）
- 本层有子文件夹或压缩包 ⇒ 它是**容器**
- 判定只有一处（`DirContents.isBook`）

**打开容器不递归合并**：

- 列出的只是它自己这一层的条目
- 子文件夹与压缩包各是一条独立条目（点一个读一个、各自是一本）
- 本层图片各自也是条目（点一张 = 从该张连读本层其余图片）
- 因此打开的页数只与本层有关、与下层书目数/总页数无关
- **打开容器只读本层图片、不并入下级**
  - **例外：本层无图的容器**——只含子目录、只含压缩包、或空壳
    —— 打开时抛错，界面给中文提示

**压缩包（CBZ/ZIP）**：

- **内部**仍按 `isArchiveImageEntry` 全深度收集
  （包内套一层书名目录是常见布局；包内分卷见非目标）
- 压缩包里没有图片时给出 0 页句柄，界面据此显示中文空态（不是一直转圈）

### 封面

**取哪一张**：

- 书 = 第一页
- **本层有图的容器 = 本层首图**
- 多子文件夹的文件夹 = 逐级下取
  - **每一层都与单层目录同一套优先级**——本层图 → 本层首个压缩包的首帧
  - 每层只开首个包，同层其余包不碰

**预取**：

- 封面**字节**由界面按需取
- 列表/柜页对**可见区 ±1 屏**内、**且封面走来源字节通路**的条目**主动预取**
  - 并发上限 4、出屏不立即淘汰
  - 本地/SAF 的 `coverUri` 行不预取
- 预取 = **取字节 + 解码进封面位图分区**，与可见行**同一把解码键**
  （就绪后可见行直接命中，不再重解、也不重复取同一份字节；票 #108 r6）
- 票 #108 E2-B 反转了旧口径「不预取封面字节」

**何时发生**：

- **容器封面的逐级下取与压缩包首页封面的解出都只在按需取封面时发生**，
  枚举期一次都不发生
- 缓存分两层：
  - 压缩包封面解出的首页按「node.id + 修改时间」**落盘**缓存
  - 所有封面字节（含目录/容器封面）另有**会话级内存字节缓存**
    （键含条目 id 与 mtime，条目数与字节数双上界，手动刷新与来源实例释放时清空）
- 探测「这个子目录是不是书」时已知的「目录内首图」直接用于封面，不再重复列同一目录

**容器行封面兜底（Komga）**：

- 取不到缩略图的容器行（类别行、收藏行等）按名称序取**第一个子项的封面**
- 子项也没有则留空
- 该封面**不随全局排序变化**

**缩放策略**：

- 浏览**列表档**的封面按**自身宽高比铺满行内封面列宽**
  - 56dp 不变；高度 = 宽度 × 比例，完整显示不裁剪
  - 解码前按占位比例避免列表跳动
- 浏览**网格档**的格子是**统一尺寸**
  - 格宽由设置列数等分、格高 = 格宽 × 固定格比例
    （高宽比 4:3 常量 `CoverLayout.GRID_CELL_ASPECT`、与封面自身比例无关）
  - 封面在格内**裁剪填满**（短边铺满、长边裁掉）
  - 因此任何比例（含超长条漫页、超宽跨页）都不改变格高、不留灰边、不出现「半截」
  - 但**格子高度上限 = 可视高 − 名字行高**（横屏 2 格等场景），
    超限时封面**等比收窄并水平居中**（盒比例仍 4:3、不拉伸），名字行始终可见
- 两档都**按本次显示宽度解码**
  （调用方给的 dp→px 向上取到 32px 整数倍分桶，解码缓存键含目标宽度）
- 比例超出兜底区间（高宽比 0.6–1.6）时按限值盒子填充裁剪（**列表档专用**；网格档一律裁剪填满）

**按显示盒裁剪解码**：

- 解码前用 `inJustDecodeBounds` 取源尺寸，按本次显示盒算出源坐标上**居中**的可见带，
  只解这一条带
  - **API 28+** 用 `ImageDecoder` 裁剪解码、裁剪与缩放一步完成
    - **目标尺寸不许 clamp**——目标尺寸与裁剪矩形是一套映射，改小就取不到那条带
  - **API 26/27** 退回 `BitmapRegionDecoder` 再缩到显示盒宽度，只缩不放
- **走带必须同时满足四条**：
  1. 带真的裁掉了像素
  2. 保留位图更小
  3. 带的瞬态峰值 ≤ 12.8MB
  4. 裁剪解码那条带同时轻过区域带与整图子采样
  - **①②③ 任一不成立就沿用整图子采样**（④ 只决定两条解码器里选哪条）
- **约束：保留位图从不比改动前（整图子采样）大**
- 峰值口径只数解码器要建的那几张位图（`Plan.peakByteCount`），**真机 RSS 峰值实测未做**
- （实现细节与逐条退路见 `core/view/CoverDecode.kt` 与 `CoverDecodeTest`）
- 阅读菜单的预览条与三档字号层级见下节

### 阅读菜单与预览条

**预览条**：

- 完整显示不裁剪
- 单格**宽度按该页真实比例**、**高度 = 预览条高 − 页数行**
  （页数在缩略图正下方居中）
- 缩略图**按预览条高向上取到 32px 整数倍**解码
  —— 票 #105 起页数行占掉预览区一行
- 格内页码字号随**面板内宽**放大并夹在 12–16sp（基准是面板内宽，不是格宽）

**三档字号层级**（基准都是面板内宽）：

- 菜单标题 = 内宽 × 0.05 夹 18–24sp
- **>** 面板页码 = 内宽 × 0.05 夹 16–24sp
- **>** 格内页码 = 内宽 × 0.035 夹 12–16sp
- 正常档成立；**极端 fontScale 下**面板页码会降到「**≥** 格内页码」并**允许省略号**
  —— 下限绑格内页码字号以保证层级不破（票 #105 r12）

**面板出现 / 消失（票 #129）**：

- 呼出时从**屏幕下缘往上滑入**、收起时**沿来路往下滑回**
- 时长 **180ms**（出现减速型、消失加速型）
- 位移取整幅高 ⇒ 两端都完全落在屏幕下缘之外；面板的内容与几何不受影响
- 时长与**出现曲线**的声明口径在 `ui/ReaderMenuTransitions.kt`（`ReaderMenuTransitionsTest` 钉它）；消失曲线直接读 `AppNav.kt` 的 `NavTransitions.EXIT_EASING`（不另起别名）
### 列表枚举性能

**每层只列一次目录**：

- 文件源（本地/SAF、SMB、WebDAV）列目录时，每层目录只列一次
- 子目录「是书还是容器」的属性探测**并发执行且有并发上限**
  - 单条探测失败降级为容器，不拖垮整表
  - 传输层故障例外：断链/认证失效照 `TransportFailure` 冒泡，不伪装成「都是容器」
- 同一目录在同一会话内二次进入命中会话级列表快照
  （会话级来源实例按连接复用）
  - **快照按容器一份、与排序方式无关**——换排序不再重列目录
  - 枚举结果保留列目录时顺手拿到的节点，因此名称/修改时间两档排序
    都**不再按 id 取节点**、比较器里没有任何 I/O
  - **发布时间档**在本次枚举里读包内 `ComicInfo.xml`，每个条目只算一次、
    按「条目 id + mtime」缓存
  - **落盘快照恢复的条目**（没有节点）在异步枚举落地前用快照里的 mtime 兜底、
    **不 resolve 也不开包**
- 文件改动按容器 mtime 失效（命中时花一次取节点比对 mtime，与条目数无关）

**mtime 变化不整层重探**：

- 仍只发 **1 次列目录**，把新结果与上次快照（会话内或落盘）
  按「条目 id + 该条目自身 mtime」比对
- 新增/删除/改名直接反映
- **子目录自身 mtime 变了只重探那一行**，未变化的行**沿用上次结论、0 次探测**
  - **两侧都取不到 mtime 的层**（SMB 共享根、部分 SAF/WebDAV 层）视同「未变」
- 探测失败的结论一律不复用、只重试失败的那几条
- 打点为 `snapshotSource=memory|disk|none` 与 `childrenCalls`/`probes`/`reused`
  （字段口径见 `Source` 的 KDoc 与 `PerfTiming`）

**显式刷新入口 = 浏览页顶部的下拉更新**：

- 只认拖拽，滚轮一律不触发
- 动作为清该容器缓存并重取容器/压缩包封面
  （走 uri 解码的本地图片封面不重取）
- **它是强制路径：清缓存 = 下次进入整层重列 + 全量重探**，
  增量复用只作用于自动失效路径

**取不到 mtime 的容器也做会话内缓存、只由手动刷新失效**：

- 相邻书（上一本/下一本）判定复用同一份会话快照、**只读**
  - 快照未命中时不列父层、不探测子目录：
    该容器本次会话未被列过时两侧邻位均为 null，界面照故事 28 提示
    「无上一本/无下一本」
  - 浏览页枚举过的层照常给邻位
  - 进阅读器后由界面在后台调一次 `Source.warmNeighbors` 补齐该层
- 缓存失效只看**容器自身**的 mtime
  - 因此对已命中缓存的父层，仅子目录**内容**的增删不会自动反映
    （要靠下拉更新，或父目录自身 mtime 变化后的增量重探）

**列表快照落盘**（按「连接 id + 容器 id」，APP 私有缓存目录）：

- 内容 = 条目清单 + 该目录自身 mtime + 写入时间 + 格式版本号，**不落盘封面字节**
- 退出 APP 后再进入同一目录：
  - mtime 未变 ⇒ **0 次列目录、0 次探测**
  - mtime 变了 ⇒ 先用快照把列表显示出来、再 **1 次列目录 + 增量重探**
- **先显示的那一帧由 `Source.snapshotEntries` 交出的快照承担**，
  界面侧先落它、再落重列结果，即**静默刷新**：不闪空白、不打断滚动
- 每条快照判 **7 天 TTL**（看写入时间，不是最后使用时间）
- **取 mtime 失败**（离线/服务器不可达）仍用快照把列表显示出来
- 下拉更新同时清该容器的内存与落盘快照
- 连接被编辑或删除时清该连接名下全部快照
- 容量上限 **2000 条或 20MB**（先到者为准，按最后使用时间淘汰）
- 格式版本号不匹配整片作废重来、不崩溃

**同步快照访问器 `Source.cachedEntries`**：

- 从阅读器返回浏览页时首帧直接落会话内快照，不列目录、不比对 mtime，
  列表**立即可见**、不闪「加载中…」
  - **例外**：直取层的反向档——那种档的整层枚举不写这份会话内列表，
    见「浏览列表按需加载」那节的代价段
  - 该键已被正向第 0 页写过时仍给出一帧
- 它**绝不做 IO**（在组合期被调用）

**冷启动（进程重启）首帧**：

- 同步访问器只看会话内存，因此首帧仍走异步路径，但该路径分两段：
  - 第一段：`Source.snapshotEntries` 交落盘快照
    （0 次列目录、0 次探测，只读本地文件）
  - 第二段：新枚举结果
- 因此**「加载中…」期间不再发生列目录/探测**
- 四个来源口径一致
  - **Komga 为会话内列表**：内存一份、不落盘、不含 mtime，
    **不是**词表里的「列表快照」，**冷启动没有它**，见上文「浏览列表按需加载」
  - 键含排序方式
### 列表首屏与封面后到

- 列表在封面未就绪时即可见、可点
  - 封面按**可见区 ±1 屏预取**（取字节 + 解码）+ 可见行按需取
  - 口径见「封面」条（票 #108）
- 封面后到不阻塞名称与点击
- 但条目列表仍在**整批子目录属性探测完成**后一次返回
  （流式列表见 Out of Scope）

### 列表条目呈现与页数

**行内内容**：

- 浏览列表行内只有封面 + 名称（长名称最多两行）
- 没有「文件夹 / 书 · N 页」副标题

**进度条**：

- 已读书目的进度条在**名称正下方、与名称左缘对齐**（条右端到名称列右缘，不做内缩）
- 网格档则是**压在封面下缘、不占布局**
- 未读的书两档都不画、因此不留空白
- 条样式两档一致：轨道 = **主题 `onSurface` 的 30% 不透明度**、
  **方头**端帽、高 **6dp**、不画 stop indicator
- **网格档**的条下另铺一层**黑 45% 暗底**
  （与条同宽同高、叠在封面下缘、不占布局；列表档没有；未读时暗底与条都不画）

**页数**：

- 文件源枚举期**不为页数**读压缩包中央目录、也不为页数列子目录
- 列表条目的页数一律为空，页数只在打开书后由 `BookHandle` 给出
- Komga 的页数来自服务器返回的 payload，照常返回但界面不显示

### SMB 连接表单

**字段**：

- 名称（可空）
- 服务器地址（可含端口，如 `192.168.1.10:1445`；不写即 445）
- 路径（`共享名/子目录`，子目录可省）
- 用户名 / 密码 / 域

**地址与路径容忍这些形态**：

- `smb://` 前缀
- 前后空白与首尾斜杠/反斜杠
- `/` 与 `\` 混用
- 前导/尾随/重复斜杠与 `.` 段
  - **含 `..` 直接拒绝**
- IPv6 字面量 `[fe80::1]:1445`
- 非数字或越界端口、空地址、空路径各有中文提示
  （**逐条见 `SmbConnectionForm` 的测试**）

**存储形状不变**：

- 仍落 host / port / share / rootPath 四个逻辑量（Room 无需迁移）
- 另有一个**非敏感**的 `portExplicit` 标志键，区分「写了 `:445`」与「省略端口」，
  只在展示名与地址回填里用
- 老配置编辑时「共享名 + 起始目录」回填成一条路径、非默认端口折进地址
- 节点 id 前缀仍按非默认端口区分（不加 IPv6 方括号
  —— id 前缀是进度键的一部分，改写法会让既有进度键失效）

### 网络来源连接表单的标签

**标签**：

- WebDAV / Komga 的「服务器地址」标签只写字段名
  —— 真机上带括号的长标签会换行并被输入框边框缺口截掉
- 字段下方**不再有任何说明文字**（票 #131 删掉了 `ConnectionField.hint` 与渲染分支）
  - 地址格式说明改由校验错误文案承载（票 #52）
  - 「不写端口时 http 按 80、https 按 443」在界面上不再显示；默认端口本来就不进存储值与连接名
    （「省略不补默认端口」的口径不变，见「连接名」一节）

**Komga 表单只保留邮箱 + 密码认证**（Basic）：

- API Key 字段从表单、表单值（`decode` 不回填）与校验里删除
- 校验缺邮箱或密码时给中文提示「请填写邮箱与密码」
- **存量 API Key 连接读取路径保留**（`KomgaConnectionConfig.apiKey` 与 `usesApiKey` 不变），
  照旧连接与浏览
- 但编辑保存时表单只带回邮箱/密码（皆为空的存量行）→ 校验拦下并要求填写（不静默失败）
- Komga 的认证失败提示（`KomgaFailure`「检查 API Key 或邮箱/密码」）不改

### 连接名

**取值与消费点**：

- 连接的可配置展示名，落 `connections.displayName` 列
- 书柜柜名、浏览页根层标题、连接列表读这个**列**
- 错误提示读来源配置的 `displayName`
  - 而配置由连接行构造时把列名作为**运行期载体**带上（载体不进 configJson）
  - 四个消费点因此恒等

**形态规则只有一处实现**（`core/source/ConnectionName.kt` 的 `connectionDisplayName`）：

- 用户填的名称优先
- **留空回落到来源自动拼名** `主机[:端口]/路径`
  - SMB：`主机[:端口]/共享名/子目录`
  - WebDAV：`主机[:端口]/DAV根/起始目录`
  - Komga：`主机[:端口]/路径`
  - 本地 = 所选文件夹名

**一律去掉 scheme**：默认名不写 scheme，但节点 id 前缀仍带 scheme、进度键不受影响。

**端口只在用户显式配置过时出现**：

- 省略不补默认端口
- 该标志只进展示名与表单地址回填，节点 id 前缀与进度键不看它

**截断与兜底**：

- 名称去首尾空白、超长按 40 码点截断（不劈代理对）
- 名称与自动拼名都拿不到时用兜底名「未知连接」

**入口**：

- 三个网络来源的连接表单新增「名称（可空）」字段（`decode` 回填）
- 本地来源在根列表里新增「重命名」
  （只改 `displayName` 列，SAF uri 不动，因此不重建会话、不失效列表快照）

**存储**：

- 用户填的名称以**非敏感** `name` 键存进 configJson
  （**不加列、不加迁移**；写入点只有表单保存一处，
  形态见 `core/source/ConnectionName.kt`）
- 存量连接没有该键 ⇒ 名称字段为空，编辑保存时才按新形态重算一次（不批量重算）

**已知代价（有意接受）**：

- 名称进了 configJson，而 configJson 是会话来源与落盘列表快照的命中判据，
  因此改名会重建一次会话、清一次该连接的快照
- **同主机同路径、不同 scheme 的两条 WebDAV / Komga 连接因此同名**
  （柜位与条目仍按连接 id 分开，但列表上分不清）

### 排序在展示层翻转

**来源接口不接方向**：

- 来源接口只接受排序方式、不接受方向（`Source.listEntries` 契约不变）
- 方向由界面按全局排序设置对来源返回的已排序结果**整份翻转**后展示
- 四个来源行为因此一致（例外见故事 14/15）

**设置存放**：

- 全局排序设置**（形态与选项见故事 14）**落 SharedPreferences（`ui/SortSettingStore.kt`）
- 条目列表只剩浏览页一处，因此它是浏览页的排序来源
- 「上次停留的位置」只记目录层级，切排序不改写它

**滚动复位**：

- **排序设置变化时浏览页两档滚动回到顶部**
  - 复位只由排序设置变化触发
  - 列表档与网格档各持一份滚动状态、各自复位
  - 换排序类别会重新枚举，新顺序落地那一帧会再复位一次
- 非排序变化不触发复位（下拉更新重列、切视图档位、进子目录/返回上级、
  从阅读器返回都照旧保持原位置）
- 滚动位置本身仍属 Out of Scope

### 启动中转与退化

**启动判定期间停在中转页**：

- 判定内容 = 读设置项与上次状态 + 按 id 取连接 + 建来源会话
- 该页显示进度指示、**不响应抽屉边缘手势**
- **启动判定所需的落盘状态**（启动页面设置、`StartupStore`）
  在启动 effect 内、第一次挂起之前同步读完
- **本项只覆盖启动判定本身（`AppNav` 的启动 effect）**，
  其余界面各自的设置读不在本口径内
  （它们读的 prefs 在 `MainActivity.onCreate` 已加载、后续是内存读，改动会牵动首帧呈现）

**导航**：

- 落地导航只做一次，但**还原后栈顶仍是中转页时补跑一次**
  （慢来源冷启动期间旋转、进程被杀后回到前台；否则该页没有任何出口）

**退化**：

- 启动目标指向的连接已不存在时：
  - 浏览目标回落首页并**清掉** `StartupStore` 里那条不可用的「上次停留的位置」
    （读库本身失败时不清：那是暂时性故障，不等于连接被删）
  - 阅读器目标先退化为上次停留的位置、仍不可解析才回落首页
- 判定/建会话/导航抛预期外异常时**降级只落首页**
  （取消照常传播，不在取消后导航）

### 会话来源的复用与释放

- 启动覆盖会话来源沿用单槽复用与已定释放路径
  —— 同一 connId 复用现实例
- 换到别的连接 / 连接被编辑或被删除 / App 退出三条路径都会释放旧实例
- 且释放一律在后台进行（不阻塞导航）
### UI 骨架

**三个主界面**：

- 浏览页：顶栏是**「视图」菜单 + 排序**
  - 视图档位 = 列表 / 网格 2 列 / 网格 3 列 / 网格 4 列，默认网格 2 列
  - 非法或缺失值回落网格 2 列；全 app 一份、跨目录层级与连接与重启保持
  - 手动刷新是**下拉更新**——只认拖拽、滚轮不触发
  - 条目形态随档位切换；两档共用枚举/方向/名称/进度/点击语义
  - **顶栏标题恒单行、放不下时末尾省略**
    - 根层 = 连接名，子层 = 条目名；渲染口径收在 `ui/TopBarTitle.kt`
    - 因此任何长度的名字都不折行、不撑高顶栏
    - 想看全名的补救是给连接起短名；不做标题展开/tooltip 与自适应缩小字号
- 阅读器：类型 3 触摸区域、菜单 overlay、横向预览条（全书页滑动）、上一本/下一本
- 导航抽屉：左缘，首页/阅读器/书柜/设置四个入口
  - 浏览历史的后退/前进只在系统返回手势与鼠标侧键，不再有抽屉入口

**鼠标左键按住拖动 = 上下滑动**：

- 适用浏览页两档与条漫模式
- 与下拉更新分层——顶部向下拖动整段仍只归下拉更新
- 单页模式不加

#### 快速定位滑条

**几何**：

- 浏览页两档的右缘各一条细滑条，宽 6dp、**本体居中于横向空档**
  - 离屏缘 = （空档 − 本体宽）/ 2
  - 空档 = 内容右留白 + 系统右缘 inset
  - 无系统右缘 inset 时空档 = 20dp ⇒ 本体右缘离屏缘 7dp、抓取带 13dp
  - 空档被系统右缘 inset 撑宽（横屏 / 三键导航把系统栏放右侧 / 挖孔）时，
    本体离屏缘随之变大、仍落在空档正中，抓取带随空档变宽
  - 票 #60：**恢复** r4 的「居中于空档」口径；
    批次 9 r2 那条「贴屏幕侧固定、中心距屏缘 10dp」已作废
- 半透明叠在内容之上；**不压封面与名称**（网格档下离封面 7dp、离屏缘 7dp）
- 右侧留白 12→20dp 的代价是每格封面窄约 8dp
- 供 1000+ 条目时一步定位

**位置与长度**（都取连续值）：

- 进度 = （首个可见**行**索引 + 行内已滚过比例）÷ 总行数
- **按行不按条目**：网格档一档多格、按条目算会让行内速度减半并在每行边界跳一格
  （票 #60 批次 9 r2）；列表档一行 = 一条、算式与旧口径一致
- **按需加载的层里分母是「已加载条数」+ 截断提示行与尾部触发件行**
  （票 #119：滑条表示的是**已加载范围内**的位置，更远的条目要先滚到底续页
  —— 总数要按需加载才知道，拖到未加载的位置也没有内容可落）
- 可见条目数按**各可见条目露出比例求和**（不用整数计数，票 #60 r6）
- **长度下限 64dp**——条目再多也不再变短；不足一屏或不足两条时不显示

**实现位置**：

- 几何与「拖动位移 → 目标条目索引」（网格档落点是该行的首条）
  是 `core/view/QuickScrollBar.kt` 的纯函数
- 手势判定（**只认主键**、**越过触摸斜率才算拖动**、**滚轮换算**）
  是 `core/input/QuickScrollBarGesture.kt` 的状态机

**出现/隐藏**：滚动即淡入 120ms、静止 1.2 秒后**只淡出一次** 200ms
（**按住或拖动期间不计时、也不重排计时**）

**带内手势的取舍（有意）**：

- 带内起手的上下拖动 = 跳到该处（不是平滑滚动列表）
- 带内鼠标滚轮**照常滚动列表**
- 带内起手的点击归滑条（可见期间这条抓取带不传点击；完全隐藏即整条移除）

#### 返回逐级

**抽屉顶层入口压在当前界面之上**：

- 抽屉的首页/书柜/设置三个顶层入口**压在当前界面之上**
  （返回因此回到进入前的界面，例如进入设置前的那个子文件夹）
- `launchSingleTop` 不叠加、不形成环；进入新入口前先收掉栈顶连续的顶层入口层

**回退栈是唯一事实来源**：

- 浏览历史是回退栈里浏览层的**镜像**
  —— 显示每一层时按实际回退栈重建后再落盘
- 随**会话结束（Activity finish）**清空；
  旋转这类非 finish 的 Activity 重建**保留**历史
- 启动落地按**落盘路径**重建整条层级链（根 → … → 上次停留层）
- **同一层重复进入 = 替换**（不追加）
- 从抽屉顶层入口**离开浏览会话**后重进连接/文件夹**不把新层级追加到已离开的旧段上**；
  收掉旧段时它**之上**的非浏览层按原顺序恢复
  （因此返回落到来源列表/书柜，而不是直接首页）
- 抽屉顶层入口从不弹浏览层因而不动历史
  ⇒ 浏览页的返回处理器只在「栈顶之下紧邻是浏览层、且镜像与栈逐层一致」时接管
  （票 #70 r3/r4）

**根路由的返回键不直接退出 APP**（票 #128）：

- **根路由（首页在栈底、抽屉关着）的返回键不直接退出 APP**
- 第一次只弹一条轻量 Toast「再按一次退出」（不退出、不打断操作）
- **2 秒内**再按才真的退出（Activity finish，会话随之按既有口径清理）
- 超时、或离开根路由（进抽屉 / 进浏览层 / 进阅读器 / 首页被压在别的层之上）即重新计数
- 接管判据是 `ui/RootBackExit.kt` 的纯函数 `atRootRoute` + 时间窗状态机 `RootBackExitState`
- 子层级返回行为不变，各自由自己的处理器接管

**进程被杀后重建**：

- 回退栈由系统还原，浏览历史按还原出来的回退栈**整体重建（幂等）**，两者逐层对应
- 导航观测点事件名见 `ui/NavEvent`，一行给出回退栈深度 + 栈顶路由 + 历史游标

**设置页**：阅读模式、旋转三选一、双击倍率、启动页面五选项、
始终从第一页打开、音量键、主题

#### 导航过渡（票 #111）

**横向滑入 300ms**：

- 返回与进入走同一条过渡
- 新屏 `translateX` 从 **±30%** → 0（与旧屏**同幅**）
- 旧屏**同向**移出 **30%** 并把 alpha 淡到 **0.55**（两屏同时动、不做错开）
- **两屏的位移与亮度四处同用减速曲线** `CubicBezier(0.05, 0.7, 0.1, 1)`
  —— 两屏位移同向、新屏起点与旧屏终点取反号
- 新屏亮度从 **0.55 → 1**（旧屏 1 → 0.55 的镜像）；冷启动的纯淡入支（没有旧屏）起点 alpha 仍是 0
- 过渡**交给系统**（`NavHost` 的四支过渡，`ui/AppNav.kt` 的 `NavTransitions`，
  按方向预先建好各支 ⇒ 一次导航只触发一次过渡）

**方向由入口显式给出**（阅读器路由参数 `enter` + 纯函数 `navTransitionDirection`，不猜方向）：

- 进入子文件夹 / 抽屉入口 / 进入阅读器 = **从右**滑入
- 返回上一级 / 抽屉返回 / 退出阅读器 = **从左**滑入
- 换书按入口（「下一本」与 `forward = true` 从右，「上一本」与 `forward = false` 从左）
- **冷启动直接落进阅读器只淡入**（那时没有旧屏）

**等页期间的呈现**：

- **阅读器等页期间新屏是主题背景色纯色、不显示加载指示，页就绪后整屏淡入 150ms**

**衔接侧是「点了立刻滑」**（票 #122）：

- 导航在点击那一帧发生，**不再等前置**
- 「打开书 + 首批解码」的前置工作（`preloadReaderOpening`，行为与预取键一字未改）
  与它的**等待**改到**阅读页侧**
  （`ReaderPrelude.await`，上限仍是 1.5s，到点/没有在飞的前置
  就由阅读页自己开书 `openAndLandReaderEntry`）
- 前置工作归会话级作用域（发起那一屏被导航销毁也带不走它）
- 过渡期的主线程帧时长由挂在导航壳上的 `core/view/NavTransitionProbe.kt` 量化
  （单帧 > **32ms** 计数，覆盖**所有**导航过渡；
  判据：连续 10 次进出 > 32ms 的帧 ≤ 2，不过关不阻塞交付）

**四条开书入口**（浏览页点击 / 启动还原 / 抽屉「阅读器」/ 阅读器内换书）：

- 走**同一套前置槽**，且**四条都是「先导航再等」**
  （票 #122 有意为之：前屏不再保持到前置就绪，
  点击/入口那一次导航立刻发生，等页期间是主题背景色纯色）
- 上限在**两侧**都有：
  - 阅读页侧那次等待是等前置到货（≤1.5s，到点由阅读页自己开书）
  - 发起侧那次 `withTimeoutOrNull{ work.await() }` 与导航无关
    （导航已在第一帧发生），它只决定这次调用何时返回，返回值被丢弃
    【交付由工作自己完成，见 `ReaderPrelude`】
- 前置工作继续在后台跑（发起侧被取消不停它）、失败不入槽
- 一份前置只属于**发起它的那次打开**（票 #122 r2/r3）：
  被顶替的世代不入槽，阅读页自己开书落地后那份迟到的也会被**退役**
  （旋转屏幕这类界面重建不再把它取走）

**「这次点击算不算数」的守卫各入口各一条**：

- 浏览页 = 组合存活标志 + 「当前要开的那一本」（`BrowserScreen`）
- 另三条 = **栈项身份**（route + entryId，
  **同 pattern 不同参数之间的离开（子文件夹 → 父目录）也算离开**）
- 导航已发生之后，「不许把 A 的句柄交给 B」由三件事共同承担：
  - 前置槽的「连接 id + 书 id」键
  - **同键过期前置的世代判据**（一份前置只属于发起它的那次打开：
    上一次打开留下的那份不得被这一次取用）
  - 「只在这个阅读页在屏幕上时落地」
  （`#122` / r2）

#### 窗口与系统栏

**窗口全幅绘制**：

- 窗口进入 edge-to-edge 并允许在挖孔/刘海区绘制
  （`LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES`），阅读器画面铺满到屏幕顶端与挖孔侧
- 列表类界面继续由 Scaffold + 顶栏消费系统栏 inset（不双重内缩）
- 贴底浮层（阅读菜单面板、跨书确认条）显式消费系统栏与挖孔 inset
- **例外**：阅读菜单面板在**手机竖屏档**不消费**底部** inset
  （票 #105 裁决 C：面板底边贴屏幕下缘，底部内边距 = 滑条行半高 + 行距 = 18dp，
  使底部行上下两段各 36dp 成立），其余视口档左/右/下三边照旧消费
- 系统栏图标明暗跟随深浅主题

**阅读器沉浸**：

- 阅读器路由在场时隐藏状态栏与导航栏、离开即恢复可见
- 接线在 `ui/ReaderSystemBars.kt`，由 `AppNav` 按**当前路由**驱动，
  而不是阅读页的组合存活期——换书时路由串不变，效果不重跑，
  旧 entry 的销毁因此不可能盖回新 entry 的隐藏
- 隐藏时行为取 `BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE`，
  边缘滑动仍能临时唤出、恢复时行为回到默认
- 系统栏隐藏后 `系统栏 ∪ 挖孔` 会塌成 0，贴底浮层的**底部 inset 因此分两支**
  （判据在纯函数 `core/view/ReaderOverlayLayout.kt`）

**系统栏占位**（底 inset > 0）：

- 用**真实栏高**（= 系统栏底 ∪ 挖孔底，与改动前逐像素相同）
- 边缘上拨**瞬态唤出**的那几秒是否也走这一支，
  取决于平台在瞬态显示期间是否把 `systemBars` 底报为非 0
  —— **本机未验证（真机观察项）**

**栏缺席**（底 inset == 0）：

- 用「挖孔底 ∪ 24dp 最小留白」
- **手机竖屏档的阅读菜单面板不消费这份底部留白**
  （票 #105 裁决 C：面板底边贴屏幕下缘，
  代价是底行连同其 48dp 命中带的下缘落进该区）

#### 名称与图标

**条目名称断行**：

- 名称按「能塞就塞」断行（最多两行、不省略号）
- 在 `]`、`-` 这类闭合/连接标点之后与数字字母交界处补零宽空格作额外断点
- 长度 ≥ 4 的 **ASCII 字母/数字串**在串内每 2 个字符也补一个断点
- 长词允许在词内断开、不引入连字符；3 字符以下与其它文字保持原子
- 并给名称文本指定贪心断行配置（API 33+ 生效）

**名称块高度**：

- 网格档的名称块**固定两行高**（`minLines` = 行数上限 = 2）
  —— 1 行名也占满两行，同一排格子因此等高、格底逐行对齐
- 列表档不固定（最小行数 1）

**启动图标**：

- 三层自适应图标（白底 + 深蓝环 + 「CV」字标；比例与色值见 `res/mipmap-anydpi-v26` 与设计说明）

- 阅读中节流保存本地

## Testing Decisions

- **只测外部行为，不测实现细节**：测试通过公共接口断言可观察结果
- **Seam ①（主）：Source 统一接口**
  - 四种实现跑同一套行为测试集（浏览条目 → 排序 → 打开书 → 按页取图 → 进度读写）
  - 本地 = 临时目录 fixture（纯 JVM）
  - WebDAV = 容器化服务
  - SMB = 容器化 Samba
  - Komga = 容器化真实实例（兼验 REST 契约与进度同步）
- **Seam ②（辅）：名称自然排序比较器**
  - 纯函数测试，入库黄金样本一律用**合成名**
    （仓库是 PUBLIC，真实书库名不进仓库）
  - 守护 Windows 兼容硬约束：`第2话`<`第10话`、符号/数字/字母/假名优先级、
    大小写、假名五十音序、中文拼音、GB2312 表外字归汉字段
  - **真实书库顺序由本地探针** `WindowsNameOrderLocalProbeTest`
    读 `references/name-order-expected.txt`（不入库）逐条比对，
    给出差异表并按「位次不一致/反序对」棘轮基线报警
    （基线常量及其重标要求写在测试里）
  - 文件不存在（干净检出）时**数据类测试 skipped**
- **绿地无先例**：以上两个 seam 即测试基线的起点，后续功能测试优先复用这两个口
- **UI 层**：Compose 交互不做大规模自动化，走手动验收清单
  （触摸区域、缩放、鼠标事件、预览）
- **反射读 Compose 内部状态的白名单：当前为空**
  - 票 #118 删掉了 `TopBarTitleTest` 里唯一一处反射——它取
    `AndroidComposeView` 的 `SemanticsOwner` → `layoutInput.maxLines`/`overflow`，
    该类在 compose-ui 里是 internal、无公开入口；与本节「只测外部行为」的取向相左
  - 该类的行数上限与省略口径现在靠**真实高度不变式**守护
    （名字再长顶栏高度不变；把 `maxLines` 拿掉即变红）
  - 但 `overflow` 的具体取值在本机量不出（Robolectric 不按宽度换行）⇒ **靠真机目视**
  - 将来若再出现「必须读组合内部状态」的用例，先在本节登记，再决定是否抽公共夹具
