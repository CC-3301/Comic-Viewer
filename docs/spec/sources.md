# Spec 分册：来源与连接

> 索引与全局约定在 `docs/SPEC.md`；本文件是它的分册，只装本领域的内容。

## User Stories

> 本册含故事 1–8。

### 来源与连接

1. 作为漫画读者，我想添加 SMB 连接（服务器地址可含端口、路径 = 共享名/子目录、用户名/密码），
   以便浏览 NAS 上的漫画库
2. 作为漫画读者，我想添加 WebDAV 连接（URL、凭据），以便浏览支持 WebDAV 的网盘/NAS
3. 作为漫画读者，我想添加 Komga 连接（服务器地址 + 凭据），以便浏览我的 Komga 服务器
5. 作为漫画读者，我想通过系统文件夹选择器（SAF）授权本地文件夹，
   以便阅读手机/平板内的漫画而不必授予全盘权限
6. 作为漫画读者，我想在同一来源下建立多个连接，以便同时访问多台 NAS/多个账号
7. 作为漫画读者，我想编辑和删除已有连接，以便维护我的来源列表
8. 作为漫画读者，当连接失败时我想看到明确的错误原因（地址不通/认证失败/超时），
   以便自行修正

## Implementation Decisions

### 文件源访问

- SMB 用成熟的开源 SMB 客户端库（smbj / jcifs-ng 二选一，动手时看哪个随机访问快）
- WebDAV 走 HTTP（PROPFIND 列目录 + Range 取数据）
- 本地走 SAF（系统文件夹选择器授权）

### CBZ/ZIP 读取

先读压缩包的中央目录、再按需跳到某一页读（seek）⇒ 能按页取图、也能做页面预览，不必整包下载

### Komga 集成

REST 接口：

- 列表：`POST /api/v1/series/list`、`POST /api/v1/books/list`（`sort=metadata.releaseDate`）
- 按页取图 API
- 进度双向同步：`PATCH /api/v1/books/{bookId}/read-progress`

**书列表的筛选条件放在请求体里**：

- 写法：按系列 `{"condition":{"seriesId":{"operator":"is","value":"<uuid>"}}}`
- 依据：上游 tag 1.26.3
- 查询串只认 `page` / `size` / `sort`
- **`series_id=` 与顶层 `seriesId` 会被服务器直接忽略**，返回的是全库的书

**根层四入口**：

- `GET /api/v1/collections`（收藏列表）
- `GET /api/v1/collections/{id}/series`（收藏内容）
  - 这个接口两种返回形状都认：Spring Data 的分页对象与纯数组
  - **服务端返回什么就显示什么**：带 `media`/`seriesId` 的条目显示成书行，其余显示成系列行

**起始浏览路径**（存进 `browsePath` 键；和 baseUrl 里的 URL 子路径不是一回事）：

- 取值 `/`、`/collections[/<id>]`、`/series[/<id>]`、`/books`、`/read`，决定 `listEntries(null)` 落到哪一层
- 不合格或没填一律回落到 `/`
- 段名是**写死的短名**（不随界面文案变）；解析时**也认最早落过的中文段**
- 「阅读过」固定按最近阅读倒序（故事 14/15 的例外）

**id 长什么样**：

- 书 id：`.../series/<seriesId>/book/<bookId>`；老进度记录用的键不变
- **没有 `seriesId` 的书**单独用 `.../book/<bookId>`（能列出、能进入、能记进度）
- 分类 / 收藏容器另用一套名字：`.../cat/<kind>`、`.../collection/<id>`

#### 分页取数上限

- 浏览各层都走服务端的 `page` / `size`
- **20 页 = 1 万条这条上限只管「一次取完整层」那条路**（反向与回退到默认做法的层，每页 500 条）
- 取满 20 页而服务器还说「还有下一页」时**不再悄悄截断**：浏览页在列表上方显示一条看得见的提示
  「只显示了前 N 条（已达到 20 页取数上限，之后的条目未显示）」（N = 本次已取条目数）
- 没撞上限就不给提示
- 排序规则与书条目 id 的形态（老进度记录的键）不因这条提示改变

#### 路径选择器按需加载

- 候选列表按页要（`page` 从 0 起），每次只取服务端一页（500 条），**滚到底再取下一页**
  —— 打开大库（8600 本）不再先拉全量 JSON、也不建全表
- 根层四项是本地写死的，一页给完
- 某页的条目全被过滤掉（收藏内容里的书不是能下钻的层）时自动往后取，不卡在「加载中…」
  - **连着跳空页最多 20 页**：跳满 20 页还没有能下钻的层就当到底，不再往后取
- 后面的页失败不清空已经取到的候选（提示留在列表上方）
- 选择器不一次取完，所以**没有截断提示**；「一次取完整层」那条路的 20 页上限也管不到它

### SMB 连接表单

**字段**：

- 名称（可空）
- 服务器地址（可含端口，如 `<host>:1445`；不写即 445）
- 路径（`共享名/子目录`，子目录可省）
- 用户名 / 密码 / 域

**地址与路径能容忍这些写法**：

- `smb://` 前缀
- 前后空白与首尾斜杠/反斜杠
- `/` 与 `\` 混用
- 前导/尾随/重复斜杠与 `.` 段
  - **含 `..` 直接拒绝**
- IPv6 字面量 `[fe80::1]:1445`
- 非数字或超范围的端口、空地址、空路径各有中文提示
  （**逐条见 `SmbConnectionForm` 的测试**）

**存的东西没变**：

- 仍然存 host / port / share / rootPath 四个字段（Room 不用迁移）
- 另有一个**不含敏感信息**的 `portExplicit` 标志，用来区分「写了 `:445`」和「没写端口」，
  只在显示名与地址回填时用
- 老配置编辑时，「共享名 + 起始目录」回填成一条路径，非默认端口折进地址
- 节点 id 前缀仍按非默认端口区分（不加 IPv6 方括号
  —— id 前缀是进度键的一部分，改写法会让已有的进度记录失效）

### 网络来源连接表单的标签

**标签**：

- WebDAV / Komga 的「服务器地址」标签只写字段名
  —— 设备上带括号的长标签会换行，并被输入框边框的缺口截掉
- 字段下方**没有任何说明文字**
  - 地址怎么写改由校验出错时的提示来说
  - 「不写端口时 http 按 80、https 按 443」在界面上不显示；默认端口本来也不进存储值与连接名
    （「省略不补默认端口」这条不变，见「连接名」一节）

**Komga 表单只留邮箱 + 密码认证**（Basic）：

- API Key 字段从表单、表单值（`decode` 不回填）与校验里都删掉了
- 缺邮箱或密码时给中文提示「请填写邮箱与密码」
- **老连接里存的 API Key 照样能读**（`KomgaConnectionConfig.apiKey` 与 `usesApiKey` 没变），照旧能连接与浏览
- 但编辑保存时表单只带回邮箱 / 密码（老数据两者都是空的）⇒ 校验会拦下并要求填写（不悄悄失败）
- Komga 的认证失败提示（`KomgaFailure`「检查 API Key 或邮箱/密码」）不改

### 连接名

**名字存在哪、谁来读**：

- 连接自己配的显示名，存在 `connections.displayName` 列
- 书柜柜名、浏览页根层标题、连接列表都读这个**列**
- 错误提示读来源配置里的 `displayName`
  - 配置是从连接行构造的，构造时把列名**顺带带上**（这个值不进 configJson）
  - 所以这四处读到的名字永远一致

**名字怎么拼，只有一处实现**：

- 用户填的名称优先
- **留空就用来源自动拼的名字** `主机[:端口]/路径`
  - SMB：`主机[:端口]/共享名/子目录`
  - WebDAV：`主机[:端口]/DAV根/起始目录`
  - Komga：`主机[:端口]/路径`
  - 本地 = 所选文件夹名

**一律不写 scheme**：默认名不带 scheme，但节点 id 前缀仍带、进度记录不受影响。

**端口只在用户自己填过时才出现**：

- 不填就不补默认端口
- 这个标志只进显示名与表单地址回填，节点 id 前缀与进度记录都不看它

**太长怎么办、什么都没有时用什么**：

- 名称去掉首尾空白，超长按 40 个字符截断（不会把 emoji 劈成两半）
- 名称与自动拼名都拿不到时用默认名「未知连接」

**在哪里填 / 改**：

- 三个网络来源的连接表单有「名称（可空）」字段（`decode` 回填）
- 本地来源在根列表里有「重命名」
  （只改 `displayName` 列，SAF uri 不动 ⇒ 不重建连接、也不让列表快照失效）

**存在哪**：

- 用户填的名称以**不含敏感信息**的 `name` 键存进 configJson
  （**不加列、不写迁移**；只有表单保存这一个写入点，拼法见 `core/source/ConnectionName.kt`）
- 老连接没有这个键 ⇒ 名称字段是空的，编辑保存时才按现在的拼法重算一次（不批量重算）

**已知代价（有意接受）**：

- 名称进了 configJson，而 configJson 是判断「能不能复用连接实例、能不能用落盘列表快照」的依据，
  所以改一次名会重建一次连接、清掉该连接的快照
- **同主机同路径、只是 scheme 不同的两条 WebDAV / Komga 连接会同名**
  （柜位与条目仍按连接 id 分开，但列表上分不清）

### 会话来源的复用与释放

- 启动时覆盖连接实例仍走「一个槽复用同一个实例」与既定的释放路径——同一个 connId 复用现有实例
- 换到别的连接 / 连接被编辑或被删除 / App 退出，这三条路都会释放旧实例
- 释放一律在后台进行（不挡导航）

### SMB 会话上的读

- **除换会话那一瞬间外**，同一条会话上**同时最多 4 条读在跑**（列目录 / 查文件信息（stat）/
  取整份字节 / 打开随机访问，四个入口各算一条；超出的排队，而不是一起冲到会话上）。
  `docs/spec/browsing.md` 里那道封面取字节的限流管的是「同时取几张封面」，
  这条管的是「同时往同一条 SMB 会话上压几条」，两者各自独立生效
- **换会话那一瞬间最坏能到 2 倍上限（8 条）**：断开前已经在跑的那批读（最多 4 条）带着**上一批**的名额
  继续跑各自的重试，重建完成时新一批又放行 4 条，两批会叠加。要让它变成任何时刻的硬上界，
  得让旧那批读重试前重新过这道限流（本次改动不做）
- **会话断开期间**（连接层故障触发重建、**重建还没失败**的那段窗口）进来的读**等一个「会话好了」的信号**，
  不在各自的 socket 上等；会话重建成功后**分批发**（一次 4 条），刚建好的会话不会被一批请求同时压住。
  重建一旦失败，进这段窗口的读就不再等（见下条）
- **会话建立失败就先等一会儿**：一次会话建立失败后（**首次建连与重建同一条判断**）1s → 2s → 4s（最多 8s）内不再
  试着建会话；这段窗口里进来的读**不排队、也不再建**，就地以失败退出
  （封面那条由 `coverBytes` 吞成 null ⇒ 屏上继续显示占位；阅读器取页照旧拿到中文提示）。会话建成的那一刻计时清零
- **建连超时 10 秒**（`CONNECT_TIMEOUT_SECONDS`）：一次失败的连接最坏就占这么久，把它压下来，
  一次会话断开的最坏等待也跟着下降；读超时（`withSoTimeout` 45 秒）是另一个量，不随它改
- 会话断开由**第一个**碰上连接层故障的读负责拆掉重建；同一批里其余的读只重试一次，
  落到那条新会话上（不再各自拆一次，把别人刚建好的会话推倒）
- **来源实例释放后（`close()`）不再建会话**：迟到的读（含排在限流上的那些）就地以失败退出，限流也一起永久关闭
- **会话建好后起一条探活**：空闲时每 30 秒主动读一次共享根，让 App 在用户之前撞上被服务端作废的死会话并重建
  （用户再翻页时用的已经是活会话）。探活走同一道限流与同一条重建链，所以算上面四个入口里的一条，
  不在限流之外另压一条到会话上；间隔内有真实读就跳过那次探活。
  失败按 30 → 60 → 120 → 240 → 最多 300 秒等，一次成功回到 30 秒；还没有会话时不探
  （没被用过的来源不会被探活拉起来联网），来源实例释放（`close()`）后探活一并停掉
- 已经打开的随机访问句柄上的后续读不过这道限流；句柄中途断开的错误仍按原样上抛
