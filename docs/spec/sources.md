## User Stories

> 本册含故事 1–8。

### 来源与连接

1. 作为漫画读者，我想添加 SMB 连接（服务器地址可含端口、路径 = 共享名/子目录、用户名/密码），
   以便浏览 NAS 上的漫画库
2. 作为漫画读者，我想添加 WebDAV 连接（URL、凭据），以便浏览支持 WebDAV 的网盘/NAS
3. 作为漫画读者，我想添加 Komga 连接（服务器地址 + 凭据），以便浏览我的 Komga 服务器
5. 作为漫画读者，我想通过系统文件夹选择器（SAF）授权本地文件夹，
   以便阅读手机/平板内的漫画而不必授予全盘权限
6. 作为漫画读者，我想在同一来源下建立多个连接，以便同时访问多台 NAS/多个账号
7. 作为漫画读者，我想编辑和删除已有连接，以便维护我的来源列表
8. 作为漫画读者，当连接失败时我想看到明确的错误原因（地址不通/认证失败/超时），
   以便自行修正

## Implementation Decisions

### 文件源访问

- SMB 用成熟开源 SMB 客户端库（smbj / jcifs-ng 择一，实现期以随机访问性能定夺）
- WebDAV 走 HTTP（PROPFIND 列目录 + Range 取数据）
- 本地走 SAF

### CBZ/ZIP 读取

解析中央目录 + 随机访问（seek），支撑按页取图与页面预览，不必整包下载

### Komga 集成

REST 接口：

- 列表：`POST /api/v1/series/list`、`POST /api/v1/books/list`（`sort=metadata.releaseDate`）
- 按页取图 API
- 进度双向同步：`PATCH /api/v1/books/{bookId}/read-progress`

**书列表筛选走请求体的条件 DSL**：

- 形状：按系列 `{"condition":{"seriesId":{"operator":"is","value":"<uuid>"}}}`
- 依据：上游 tag 1.26.3
- 查询串只认 `page`/`size`/`sort`
- **`series_id=` 与顶层 `seriesId` 会被服务器静默忽略**，返回全库的书

**根层四入口**：

- `GET /api/v1/collections`（收藏列表）
- `GET /api/v1/collections/{id}/series`（收藏内容）
  - 该端点两种响应形状都认：Spring Data 分页对象与纯数组
  - **按服务端返回什么就渲染什么**：带 `media`/`seriesId` 的条目渲染为书行、其余为系列行

**起始浏览路径**（落 `browsePath` 键，与 baseUrl 里的 URL 子路径不同义）：

- 取值 `/`、`/collections[/<id>]`、`/series[/<id>]`、`/books`、`/read`，
  决定 `listEntries(null)` 落到哪一层
- 非法/缺失一律回落 `/`
- 段名是**稳定 token**（不随界面文案变）；解析**兼容首轮落过的中文段**
- 「阅读过」固定按最近阅读倒序（故事 14/15 的例外）

**id 形状**：

- 书 id：`.../series/<seriesId>/book/<bookId>`，存量进度键不变
- **没有 `seriesId` 的书**用 `.../book/<bookId>` 单独表达（能列出、能进入、能记进度）
- 分类/收藏容器用独立命名空间：`.../cat/<kind>`、`.../collection/<id>`

#### 分页取数上限（票 #119）

- 浏览各层都走服务端 `page`/`size`
- **20 页 = 1 万条这条上限只作用在「一次取完整层」的路径上**
  （反向档与回退默认实现的层，每页 500 条）
- 取满 20 页而服务器仍说「还有下一页」时**不再静默截断**：
  浏览页在列表上方显示一条可见提示
  「只显示了前 N 条（已达到 20 页取数上限，之后的条目未显示）」（N = 本次已取条目数）
- 未撞上限不给提示
- 排序口径与书条目 id 形态（存量进度键）不因这条提示改变

#### 路径选择器按需加载（票 #119 步骤 2）

- 候选列表收 `page`（从 0 起）、每次只取服务端一页（500 条），**滚到底再取下一页**
  —— 打开大库（8600 本）不再先拉全量 JSON + 建全表
- 根层四项是本地常量、一页给完
- 某页的条目全被过滤（收藏内容里的书不是可下钻的层）时自动往后取，不卡在「加载中…」
  - **连跳空页有 20 页上限**：跳满 20 页仍没有可下钻的层即当终止，不再往后取
- 后续页失败不清空已取到的候选（提示留在列表上方）
- 选择器不一次取完，因此**没有截断提示**；「一次取完整层」那条路径的 20 页上限不作用于它

### SMB 连接表单

**字段**：

- 名称（可空）
- 服务器地址（可含端口，如 `192.168.1.10:1445`；不写即 445）
- 路径（`共享名/子目录`，子目录可省）
- 用户名 / 密码 / 域

**地址与路径容忍这些形态**：

- `smb://` 前缀
- 前后空白与首尾斜杠/反斜杠
- `/` 与 `\` 混用
- 前导/尾随/重复斜杠与 `.` 段
  - **含 `..` 直接拒绝**
- IPv6 字面量 `[fe80::1]:1445`
- 非数字或越界端口、空地址、空路径各有中文提示
  （**逐条见 `SmbConnectionForm` 的测试**）

**存储形状不变**：

- 仍落 host / port / share / rootPath 四个逻辑量（Room 无需迁移）
- 另有一个**非敏感**的 `portExplicit` 标志键，区分「写了 `:445`」与「省略端口」，
  只在展示名与地址回填里用
- 老配置编辑时「共享名 + 起始目录」回填成一条路径、非默认端口折进地址
- 节点 id 前缀仍按非默认端口区分（不加 IPv6 方括号
  —— id 前缀是进度键的一部分，改写法会让既有进度键失效）

### 网络来源连接表单的标签

**标签**：

- WebDAV / Komga 的「服务器地址」标签只写字段名
  —— 真机上带括号的长标签会换行并被输入框边框缺口截掉
- 字段下方**不再有任何说明文字**
  - 地址格式说明改由校验错误文案承载
  - 「不写端口时 http 按 80、https 按 443」在界面上不再显示；默认端口本来就不进存储值与连接名
    （「省略不补默认端口」的口径不变，见「连接名」一节）

**Komga 表单只保留邮箱 + 密码认证**（Basic）：

- API Key 字段从表单、表单值（`decode` 不回填）与校验里删除
- 校验缺邮箱或密码时给中文提示「请填写邮箱与密码」
- **存量 API Key 连接读取路径保留**（`KomgaConnectionConfig.apiKey` 与 `usesApiKey` 不变），
  照旧连接与浏览
- 但编辑保存时表单只带回邮箱/密码（皆为空的存量行）→ 校验拦下并要求填写（不静默失败）
- Komga 的认证失败提示（`KomgaFailure`「检查 API Key 或邮箱/密码」）不改

### 连接名

**取值与消费点**：

- 连接的可配置展示名，落 `connections.displayName` 列
- 书柜柜名、浏览页根层标题、连接列表读这个**列**
- 错误提示读来源配置的 `displayName`
  - 而配置由连接行构造时把列名作为**运行期载体**带上（载体不进 configJson）
  - 四个消费点因此恒等

**形态规则只有一处实现**）：

- 用户填的名称优先
- **留空回落到来源自动拼名** `主机[:端口]/路径`
  - SMB：`主机[:端口]/共享名/子目录`
  - WebDAV：`主机[:端口]/DAV根/起始目录`
  - Komga：`主机[:端口]/路径`
  - 本地 = 所选文件夹名

**一律去掉 scheme**：默认名不写 scheme，但节点 id 前缀仍带 scheme、进度键不受影响。

**端口只在用户显式配置过时出现**：

- 省略不补默认端口
- 该标志只进展示名与表单地址回填，节点 id 前缀与进度键不看它

**截断与兜底**：

- 名称去首尾空白、超长按 40 码点截断（不劈代理对）
- 名称与自动拼名都拿不到时用兜底名「未知连接」

**入口**：

- 三个网络来源的连接表单新增「名称（可空）」字段（`decode` 回填）
- 本地来源在根列表里新增「重命名」
  （只改 `displayName` 列，SAF uri 不动，因此不重建会话、不失效列表快照）

**存储**：

- 用户填的名称以**非敏感** `name` 键存进 configJson
  （**不加列、不加迁移**；写入点只有表单保存一处，
  形态见 `core/source/ConnectionName.kt`）
- 存量连接没有该键 ⇒ 名称字段为空，编辑保存时才按新形态重算一次（不批量重算）

**已知代价（有意接受）**：

- 名称进了 configJson，而 configJson 是会话来源与落盘列表快照的命中判据，
  因此改名会重建一次会话、清一次该连接的快照
- **同主机同路径、不同 scheme 的两条 WebDAV / Komga 连接因此同名**
  （柜位与条目仍按连接 id 分开，但列表上分不清）

### 会话来源的复用与释放

- 启动覆盖会话来源沿用单槽复用与已定释放路径
  —— 同一 connId 复用现实例
- 换到别的连接 / 连接被编辑或被删除 / App 退出三条路径都会释放旧实例
- 且释放一律在后台进行（不阻塞导航）
