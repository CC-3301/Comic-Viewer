# Spec 分册：UI 骨架

> 索引与全局约定在 `docs/SPEC.md`；本文件是它的分册，只装本领域的内容。

> 本册无故事条目，全是实现决策。

## Implementation Decisions

### UI 骨架

**三个主界面**：

- 浏览页：顶栏是**「视图」菜单 + 排序**
  - 视图四种：列表 / 网格 2 列 / 网格 3 列 / 网格 4 列，默认网格 2 列
  - 值非法或缺失就回落网格 2 列；全 app 一份，跨目录层级、跨连接、跨重启都保持
  - 手动刷新是**下拉更新**——只认拖拽、滚轮不触发
  - 条目长什么样随视图变；列表视图与网格视图共用「列目录 / 方向 / 名称 / 进度 / 点击」这套含义
  - **顶栏标题恒单行、放不下时末尾省略**
    - 根层 = 连接名，子层 = 条目名
    - 因此任何长度的名字都不折行、不撑高顶栏
    - 想看全名的补救是给连接起短名；不做标题展开/tooltip 与自适应缩小字号
  - **标题整块可点**：点开路径菜单（`/` 与起点层的全部一级目录），见下「顶栏标题路径菜单」
- 阅读器：类型 3 触摸区域、菜单 overlay、横向预览条（全书页滑动）、上一本/下一本
- 导航抽屉：左缘，首页/阅读器/书柜/设置四个入口
  - 浏览历史的后退/前进只在系统返回手势与鼠标侧键，不再有抽屉入口

**鼠标左键按住拖动 = 上下滑动**：

- 适用浏览页两种视图与条漫模式
- 与下拉更新各管一段——在顶部向下拖整段仍只算下拉更新
- 单页模式不加

#### 快速定位滑条

**几何**：

- 浏览页两种视图的右缘各一条细滑条，宽 6dp、**本体居中于横向空档**
  - 离屏缘 = （空档 − 本体宽）/ 2
  - 空档 = 内容右留白 + 系统右缘 inset
  - 无系统右缘 inset 时空档 = 20dp ⇒ 本体右缘离屏缘 7dp
  - 空档被系统右缘 inset 撑宽（横屏 / 三键导航把系统栏放右侧 / 挖孔）时，
    本体离屏缘随之变大、仍落在空档正中
- **能按住的范围（抓取带）从屏幕右缘起算最少 32dp**（触摸与鼠标同一套；
  本体仍只占其中靠屏缘那 7–13dp 一段，视觉一个像素都不变）
  - 空档 20dp 下 32dp 中有 **12dp 压在内容区**上——这是加宽的已知代价
  - 空档被撑宽时抓取带随空档变宽（不小于 32dp），本体因此整个落在抓取带内
  - 滑条**完全隐藏**时整条抓取带不组合 ⇒ 右缘照常可点条目、可拖列表
- 半透明叠在内容之上；**视觉上不压封面与名称**（网格视图下离封面 7dp、离屏缘 7dp；抓取带另计，见上）
- **按住 / 拖动期间**本体取强调橙（`ui/AccentColor.ACCENT_ORANGE`）且不透明，松手回半透明灰
  （变橙是**输入态**，不是「滑条可见」态——纯滚动时现身仍是灰色）
- 右侧留白 12→20dp 的代价是每格封面窄约 8dp
- 供 1000+ 条目时一步定位

**位置与长度**（都取连续值）：

- 进度 = （首个可见**行**索引 + 行内已滚过比例）÷ **可滚动行数**（= 总行数 − 可见行数，下限 1）
  —— 分母取可滚动行数才可能在到底时贴住轨道底；拖动时反过来算也用同一个分母（两条路互逆）
- **按行不按条目**：网格视图一行多格、按条目算会让行内速度减半并在每行边界跳一格
  —— 列表视图一行 = 一条
- **拖动落点 = 行 + 行内偏移**（连续值）：反算时不再取整到整行，与几何互为逆运算
  —— 取整到整行时网格视图会一次跳一整行（设备上就是「一排排封面滚」）
- **拖动期间本体连续跟手**：拖动支路把落点的**行内偏移**按行距折算成比例、与本地行索引
  一起喂给几何（换算与屏内比例同一函数）——本体在两条目之间连续推进，不按条目一格一格跳；
  本地索引不等滚动状态回读（跟手无滞后的取舍不变）。与松手后回读的比例差一段顶部留白：
  回读值含落点吃掉的留白（网格视图非零），拖动中只叠行内偏移、不叠留白段，差值折算到本体位置不足一格
- 拖动落点**吃掉顶部留白**（第 0 项除外）：目标行上沿贴视口上沿，上方不露留白与上一行的名字
  —— 与「停在原位置」同一套算法（见 `docs/spec/browsing.md`；拖动多一段行内偏移）
- **按需加载的层里「总条目数」取「已加载条数 + 截断提示行与尾部触发件行」**
  （滑条表示的是**已加载范围内**的位置，更远的条目要先滚到底续页
  —— 总数要按需加载才知道，拖到未加载的位置也没有内容可落）
- 可见条目数按**各可见条目露出比例求和**（不用整数计数）
- **长度下限 64dp**——条目再多也不再变短；不足一屏或不足两条时不显示

**实现位置**：

- 几何与「拖动位移 → 目标落点（行首条目序号 + 行内偏移）」收在一处纯函数；拖动落点那一段留白
  由 `ui/QuickScrollBarOverlay.kt` 的 `quickScrollBarLandingOffsetPx` 按同一套算法加（与 `restoredLandingOffsetPx` 同一处）
- 手势判定（**只认主键**、**越过触摸斜率才算拖动**、**滚轮换算**）收在一处状态机

**出现/隐藏**：滚动即淡入 120ms、静止 1.2 秒后**只淡出一次** 200ms
（**按住或拖动期间不计时、也不重排计时**）

**带内手势怎么分（有意这样定）**：

- 带内起手的上下拖动 = 跳到该处（不是平滑滚动列表）
- 带内鼠标滚轮**照常滚动列表**
- 带内起手的点击归滑条（可见期间这条 32dp 不传点击；完全隐藏即整条移除）

#### 顶栏标题路径菜单

**入口与内容**：

- 浏览页顶栏**标题整块可点**（标题规则不变：根层＝连接名、子层＝条目名）；点开下拉菜单做浏览层跳转
- 菜单 = 连接起点层（文案 `/`）＋起点层的**全部一级目录**（含当前所在那一条），
  **不是**只有当前路径上那一条
  - 只列目录（`isBook = false`），不列书；文案就是条目名
  - 一级目录**全部列出**（不按条数截断）、名称升序；顺序与全局排序设置无关
  - **菜单窗口最多 10 行**，超出的在菜单内滚（不许它随目录数长成整屏）
  - Komga 恒为四入口（收藏 / 系列 / 书籍 / 阅读过）：那是写死的固定四项，不走网络、不参与排序
    - 起始路径正好落在某一类本身时（`/series` 这类），那一项标成「就是起点层」
      （两者同一屏内容，指回起点层才不会压出内容相同的一层）
  - 一级目录名称升序、`/` 恒在最上；一层一条目录都没有时菜单只有 `/`
- **不弹菜单**的三种情形（标题不挂点击）：
  - 停在起点层（浏览链只有一层）：菜单里列的都是身后那张列表已经列着的一级目录
  - 链首的容器不是连接起点层（`containerId != null`，这条链不算数）
  - 一级目录清单还没到手（首次取数中 / 取失败）；下拉更新时会再试

**这些目录从哪来**：

- 先读**内存里的缓存**（`Source.cachedTopLevelEntries`，同步、零网络）：文件源的列表快照与排序方式无关，
  走过根层的会话里恒命中；Komga 的四入口恒可给
- 没有才现取一次（`Source.topLevelEntries`，固定按名称排，切到 IO 线程）；实现方保证之后的调用不再走网络
  ——**冷启动直接落到深层**（这次打开 APP 没列过根层）这类情形就是这一支，会真走一次列目录
- 清单到手之前只是不给入口，**不阻塞**浏览页
- 顶层一条目录都没有时菜单只有 `/`（仍可用来回起点层）

**跳转语义**：

- 点菜单项走与点容器同一条导航通路（先装好目标层快照、再导航）
- 目标已在浏览链上（`/`、当前路径上的那一级目录）⇒ 链**截到目标层**（`起点层 → 目标`）
- Komga 标了「就是起点层」的那一项 ⇒ 目标就是起点层（不是分类容器）
- 目标**就是当前层**（在 A 层又选 A）⇒ **不导航**，只刷新这一层：
  跳过去只会压出内容相同的一层，返回看起来没反应
- 目标不在链上（兄弟目录、Komga 的四入口）⇒ 链**钉成** `起点层 → 目标`：
  跳转前那一段丢弃，从目标层返回因此回**起点层（`/`）**
- 跳转清掉前进栈（与「导航到新位置」一样）

**形态**：判定收在一个**纯函数**（入参 = 浏览链 + 顶层条目，
出参 = 菜单项；每项 = 文案 + 目标层 + 链底），
呈现收在一个**顶栏小件**（入参 = 标题文案 + 菜单项 + 点选回调）。
纯函数不读全局状态、不碰导航；小件不取数、不自己导航；跳转复用点容器那条通路。

**守护**：单测钉纯函数的边界（起点层 / 链不可信 / 全部一级目录 / 只列目录 / 不按条数截断 /
名字随目标层带 / 目标就是当前层 / 起点层那一项）；
「不在链上的目标把链钉成 `起点层 → 目标`、返回落起点层」由导航层用例（`BrowserBackStackSyncTest`）钉；
「Komga 四入口与起始路径无关、起始路径那一项标成起点层」由来源用例（`KomgaSourceTest`）钉；
菜单窗口的 10 行上限与小件本身走设备目视（与顶栏行数上限同一条规则）。

#### 返回逐级

**抽屉顶层入口压在当前界面之上**：

- 抽屉的首页/书柜/设置三个顶层入口**压在当前界面之上**
  （返回因此回到进入前的界面，例如进入设置前的那个子文件夹）
- 顶层入口不叠加、不形成环；进入新入口前先收掉栈顶连续的顶层入口层

**返回栈说了算**：

- 浏览历史是回退栈里浏览层的**镜像**
  —— 显示每一层时按实际回退栈重建后再落盘
- 随**会话结束（Activity finish）**清空；
  旋转这类非 finish 的 Activity 重建**保留**历史
- 启动落地按**落盘路径**重建整条层级链（根 → … → 上次停留层）
- **同一层重复进入 = 替换**（不追加）
- 从抽屉顶层入口**离开浏览会话**后重进连接/文件夹**不把新层级追加到已离开的旧段上**；
  收掉旧段时它**之上**的非浏览层按原顺序恢复
  （因此返回落到来源列表/书柜，而不是直接首页）
- 抽屉顶层入口从不弹浏览层因而不动历史
  ⇒ 浏览页的返回处理器只在「栈顶之下紧邻是浏览层、且镜像与栈逐层一致」时接管
- **抽屉开着时内容层各屏的返回处理器一律让路**：那次返回只关抽屉（`LocalDrawerIsClosed`，
  由 `AppDrawer` 在 `ModalNavigationDrawer` 的 content 槽提供，这条判断收在 `contentBackEnabled`）

**根路由的返回键不直接退出 APP**：

- **根路由（首页在栈底、抽屉关着）的返回键不直接退出 APP**
- 第一次只弹一条轻量 Toast「再按一次退出」（不退出、不打断操作）
- **2 秒内**再按才真的退出（Activity finish，会话随之按原样清理）
- 超时、或离开根路由（进抽屉 / 进浏览层 / 进阅读器 / 首页被压在别的层之上）即重新计数
- 这条判断收在一处纯函数 + 时间窗状态机
- 子层级返回行为不变，各自由自己的处理器接管（抽屉开着时同样让位，见上）

**进程被杀后重建**：

- **回退栈被系统还原时**，浏览历史按还原出来的回退栈**整体重建（幂等）**，两者逐层对应
- **恢复落在非浏览目的地（设置 / 首页 / 书柜）时**：该顶层路由**之下**那段层级链一并重建
  （链随顶层落点记录一起落盘，见 `ui/StartupStore.kt` 的 `topLevelBrowseChain`），
  返回因此先逐级回到那段链、再回到栈底根首页；
  这份链只在「停在顶层入口」那一帧写，**旧数据没有它就不建链**（不拿「上次停留的浏览路径」兜底）；
  链指向的连接**已被删**（读到该 id、但没有这一行——不论第几次读）时同样不建链，
  **两次读库都失败**（暂时性故障）才保留链。
- 导航日志一行给出：返回栈深度 + 栈顶路由 + 当前在第几层

**设置页**：阅读模式、旋转三选一、双击倍率、启动页面五选项、
始终从第一页打开、音量键、主题

#### 导航过渡

**只有进出阅读器有动画，其余一律硬切**；进出阅读器是**静态背景滑动**——一次过渡里**只有一屏动**，
被盖住的另一屏原地静止、当背景：

| 导航点 | 过渡 | 时长 / 曲线 |
|---|---|---|
| **文件夹 → 阅读器（进）**（含抽屉的「阅读器」入口与冷启动落地） | 新屏（阅读页）从**右**滑入（+100% → 0）；旧屏（浏览页）**原地静止**（位移恒 0）当背景 | **350ms** + `CubicBezier(0.35, 0.7, 0.7, 1)`（减速型：起步快、末尾缓停） |
| **阅读器 → 文件夹（出）** | 旧屏（阅读页）从 0 → **+100%** 往**右**滑出；新屏（浏览页）**原地静止**当背景 | **300ms** + `CubicBezier(0.4, 0, 1, 1)`（加速型：起步慢、末尾冲出屏幕） |
| 层级导航（文件夹之间 / 返回上级 / 抽屉的首页·书柜·设置入口 / 书柜进柜） | **硬切**（零过渡、瞬间换屏） | — |
| 换书（上一本 / 下一本 / 跨书条） | **硬切** | — |

- **位移由 `NavHost` 自己的过渡给**：动的那一屏走框架的滑动（进 = 新屏 `slideIntoContainer` 从右滑入；
  出 = 旧屏 `slideOutOfContainer` 往右滑出），另一屏走一条 alpha 恒 1 的过渡——只把它留在屏上、位移恒 0
  （那一屏若写成 `None`，它当帧就不在屏上，滑动屏让开的位置会露出窗口底色）。
  **动画不由我们自己驱动**：没有按屏持有的进度动画，也没有给每屏套一层壳（每次导航的过渡对象由框架新建，初值在同一帧内定下）。
- **动的那一屏 = 画在最上面的那一屏**：`NavHost` 的 `transitionSpec` 给目标屏算 zIndex——进 `+1`、出 `−1`
  （`NavHost.kt` 的 `zIndices`）。因此**进的那一屏在最上面**（新屏滑入盖住旧屏）、**出的那一屏在最上面**
  （旧屏滑出露出下面的新屏）；让被压住的那一屏去动，它动得再对也看不见，看出来的就是「瞬间换屏」。
- **一次过渡只有一屏动**：滑动全程，没被滑动屏挡住/让开的那一侧始终是另一屏的完整画面——滑到一半时，
  另一半就是那一屏（进 = 静止的浏览页；出 = 底下静止的浏览页）。
- 时长：进 **350ms**、出 **300ms**；曲线两向各一条——**进入时减速停下**（`CubicBezier(0.35, 0.7, 0.7, 1)`）、
  **离开时加速让开**（`CubicBezier(0.4, 0, 1, 1)`，起步慢、末尾冲出屏幕）。时长与曲线各自只有一处出处
  （纯函数 / 常量）。
- 位移幅度 = **容器自己的宽度**（框架按滑动方向那一侧的容器尺寸算），幅度 100%；不做错开、不做亮度渐变。
- **静止侧正文当帧就在、且过渡全程必须真的被画出来**：过渡里出现整屏底色/黑即不过关——静止侧是这次形态的前提；
  退场过渡的时长就是「旧屏还在」的窗口（硬切没有这个窗口，退场屏当帧就不在）。
- **新屏没就绪时就是纯黑**：进的那一屏（含冷启动落地）当帧就挂正文（首图已在手），
  没就绪时屏上就是**黑底**（根背景恒黑、不出转圈，见下面「等页期间的呈现」）；
  首图就绪**直接呈现**——没有纯色底壳、也不等帧数；正文挂上后按「等页期间的呈现」走。
  出的那一屏（浏览页）当帧挂正文。浏览页「首帧就是内存快照 / 列表立即可见」因此不再有例外（见 `docs/spec/browsing.md`）。
- **冷启动落地也是进的那一屏**：没有交叉淡变与匀速曲线，也没有只给冷启动例外用的方向参数与路由模板。
  落地的旧屏 = 刚落盘的浏览层，**允许它还在加载**（快照多数情况已就绪；
  没就绪时露「加载中…」可接受）。
- **导航前提前装好目标层的快照**：下面这四类导航在换屏前就装，**不论这一跳是硬切还是滑动**
  （浏览页点条目下钻 / 进连接根层 / 启动重建 / 鼠标前进侧键；前进侧键从阅读器过来时是**滑动过渡**，提前装一样成立
  —— 新屏同样要目标层那份列表）。`Source.primeCachedEntries` **只读本地落盘快照**（不列目录、不去问）
  ⇒ 新屏「出生」当帧就有内容，不再先空一下「加载中…」。装快照与导航本身在**同一个
  临界区**里跑（进程内一把公平锁 `withPrimedLayer`），因此两次快速点击的先后 = 点下去的先后（不会因为装快照读得慢而乱序）。
  **代价**：导航前多一次读本地快照（在 `Dispatchers.IO`）；读不到（来源未就绪 / 没有落盘快照，
  如 Komga）就当没做，照旧导航。
  **不在这四类里的两跳**：**换书不适用**（它没有「目标浏览层」，新屏是阅读页）——仍是硬切 + 等页窗口，见下；
  **返回上级 / 系统返回也不装**（那是系统弹栈，没有应用层导航入口）——它的首帧照旧来自该层**自己此前列目录留下的**
  内存快照（该层被显示过就有）；**这份快照有例外**：直取层的反向不写它，因此那时（**且这个键还没被第 0 页写过时**）
  从阅读器返回没有内存首帧（先显示「加载中…」；这个键被正向第 0 页写过时仍给出一帧，只是长度 = 第 0 页），
  权威表述见 `docs/spec/browsing.md` 的「浏览列表按需加载」一节**代价**段。
  写法与 `snapshotSource=` 的归属变化见 `docs/spec/browsing.md` 的「提前装好目标层的快照」段。
- **硬切没有过渡窗口**：退场屏立刻不在（层级导航与换书因此没有「过渡期旧屏还能点」这一段）。
- 换书硬切后，新书还没就绪的那一瞬间：书**还没打开**时与进的那一屏同一条规则——**黑底**、首图就绪就直接呈现
  （见上面「新屏没就绪时就是纯黑」条，四条开书入口共用）；书已打开、页没到位时同样是**黑底**（见下），不会显示上一本的页面。
- 系统「移除动画」为开时直接落在终值

**等页期间的呈现**：

- **什么时候算就绪 = 任一页到位**：某一页画出了图、或确定失败、或空书，三者任一即就绪
  （失败也放行，否则失败文案与重试按钮会一直不可见；入口页在解码完成前离开组合也能就绪）
- **首批窗口**（有页可画、入口页还没到位；空书不算）：
  - 根背景是**黑底**：从进屏到就绪一路黑底、不随就绪变
  - 入口页那一格是**空占位、不画进度圈**；其余未解码页照旧显示进度圈
- **整屏淡入**时长按**入口页那一页的图**定：
  - 图已在手（首帧命中解码缓存、自己不会淡）⇒ 整屏补 **150ms**
  - 图刚到、自己会慢慢显 ⇒ 整屏**立即**（0ms，只留图片自己那条）
  - 还没有图（失败 / 空书 / 首图未到）⇒ 整屏走 **150ms**
- 页内容那条「慢慢显」的层**只管页内容**：菜单面板与跨书确认条在它之外 ⇒
  书已落地时点中区呼出菜单**立刻**可见；书还没落地时点中区不呼出
- 位图从无到有走 **150ms** 淡入（不是一帧全亮）

**衔接侧是「点了立刻滑」**：

- 导航在点击那一帧发生，**不等前置**
- 「打开书 + 首批解码」的前置与它的等待改到**阅读页侧**：上限 **1.5s**，到点由阅读页自己开书
- 前置工作挂在**会话级**（发起那一屏被导航销毁也带不走它）
- 过渡期主线程单帧 > **32ms** 计数；判断标准：连续 10 次进出里 > 32ms 的帧 ≤ 2；不过关不阻塞交付

**四条开书入口**（浏览页点击 / 启动还原 / 抽屉「阅读器」/ 阅读器内换书）都走**同一条开书入口通道**：

- 入口交「哪本书 + 这次请求算不算数的判断 + 怎么进阅读器」；通道负责领世代号、导航与会话级前置
- 四条都是**先导航再等**（前屏不保持到前置就绪；等页期间是黑底纯色）
- 前置在后台继续跑（发起侧被取消不停它）；失败不入槽
- 一份前置只属于**发起它的那次打开**：被顶替的世代不入槽；迟到的那份在阅读页自己开书落地后退役
  （旋转屏幕这类界面重建不再把它取走）
- 「这次点击算不算数」四条入口共用**同一套请求登记**（`ui/session/OpenBookRequests.kt`）：
  领 token 之外还记下**栈项身份**（route + entryId；同 pattern 不同参数之间的离开也算离开），
  各入口另交自己那条组合存活标志（浏览页 = 这一屏的组合存活标志）
- 导航已发生之后，「不许把 A 的句柄交给 B」由三件事共同承担：
  前置槽的「连接 id + 书 id」键、同键过期前置的世代判断、「只在这个阅读页在屏幕上时落地」

#### 窗口与系统栏

**窗口全幅绘制**：

- 窗口进入 edge-to-edge 并允许在挖孔/刘海区绘制，阅读器画面铺满到屏幕顶端与挖孔侧
- 列表类界面继续由 Scaffold + 顶栏消费系统栏 inset（不双重内缩）
- 贴底浮层（阅读菜单面板、跨书确认条）显式消费系统栏与挖孔 inset
- **例外**：阅读菜单面板在**手机竖屏**不消费**底部** inset
  （裁决：面板底边贴屏幕下缘，底部内边距 = 滑条行半高 + 行距 = 18dp，
  使底部行上下两段各 36dp 成立），其余几种窗口尺寸左/右/下三边照旧消费
- 系统栏图标明暗跟随深浅主题

**阅读器沉浸**：

- 阅读器路由在场时隐藏状态栏与导航栏；**离开当帧就恢复**
- 隐藏与恢复**都按当前路由驱动**，而不是阅读页的组合存活期 ⇒ 换书时效果不重跑、
  旧页面的销毁不可能盖回新页面的隐藏
- **列表界面按「稳定版」系统栏 inset 布局**（`ui/SystemBarInsets.kt` 的 `LocalStableSystemBarInsets`，提供点
  在 `MainActivity`）：取栏可见时那一份，栏被隐藏（阅读器沉浸）时不再变小——否则那份变化落在过渡中间，
  静止背景往上跳、被露出的那一屏往下跳并整块重排。**顶栏也要用这一份**（`stableTopAppBarInsets`）：
  `TopAppBar` 按自己的 `windowInsets` 给状态栏留位、不读 `Scaffold` 的 `contentWindowInsets`，
  那一处不冻结同样会跳（顶栏内容与 `Scaffold` 正文偏移都跟着它）。阅读器自己的浮层照旧读实时的系统栏（有意分两支）
- 隐藏时边缘滑动仍能临时唤出系统栏、恢复时行为回到默认
- 系统栏隐藏后 `系统栏 ∪ 挖孔` 会塌成 0，贴底浮层的**底部 inset 因此分两支**
  （这条判断收在一处纯函数）

**系统栏占位**（底 inset > 0）：

- 用**真实栏高**（= 系统栏底 ∪ 挖孔底，与改动前逐像素相同）
- 边缘上拨**瞬态唤出**的那几秒是否也走这一支 **本机未验证**（设备观察项）

**栏缺席**（底 inset == 0）：

- 用「挖孔底 ∪ 24dp 最小留白」
- **手机竖屏下的阅读菜单面板不消费这份底部留白**
  （裁决：面板底边贴屏幕下缘，
  代价是底行连同其 48dp 命中带的下缘落进该区）

#### 名称与图标

**条目名称断行**：

- 名称按「能塞就塞」断行（最多两行、不省略号）
- 在 `]`、`-` 这类闭合/连接标点之后与数字字母交界处补零宽空格作额外断点
- 长度 ≥ 4 的 **ASCII 字母/数字串**在串内每 2 个字符也补一个断点
- 长词允许在词内断开、不引入连字符；3 个字符以下与其它文字不拆
- 并给名称文本指定贪心断行配置（API 33+ 生效）

**名称块高度**：

- 网格视图的名称块**固定两行高**（固定两行 = 行数上限）
  —— 1 行名也占满两行，同一排格子因此等高、格底逐行对齐
- 列表视图不固定（最少 1 行）

**启动图标**：

- 三层自适应图标（白底 + 深蓝环 + 「CV」字标；比例与色值见设计说明）
