# ADR 0001：按票渐进深化，判据一条不改

## 背景（大白话）

票 #180–#186 这七张票不修 bug、不加功能，只做一件事：把散在各处、彼此纠缠的代码收成一个个「自己的事自己管」的模块。

原来的形态是：同一条规则在两三个地方各写一遍（取数重试、缓存键的拼法、指针判定），或者一段逻辑被劈成两半放在两个文件里（首屏的顺序约束在一处、分页状态在另一处），改一处要记得改另一处，忘了就出问题。收成模块之后，规则只有一个出处，调用方只需要知道「给我这一层的首屏」「喂一帧」，不用知道里面怎么算。

为什么一票一票来：一次动一大片，出问题时分不清是哪一处引起的；这类改动又最容易在「顺手整理」时悄悄改掉行为。

## 决策

1. **一票一个模块，一票一次提交。** 每票实施完先跑双轴代码审查（规范轴：坏味道与仓库文档规则；规格轴：票面验收标准与规格判据），按结论收口、门禁通过，再进下一票。
2. **每票的硬约束：判据一条不改、行为不变。** 只改结构，不改结果。涉及键的改动必须**键值逐字不变**（票 #182），保证升级安装后既有缓存照旧命中。
3. **依赖由构造传入，装配收在一处。** 模块不读全局单例；漏配依赖是编译期或启动期可见的错误（当场抛），不静默降级。进程级实例由装配点持有，会话级实例由组合根持有并经组合树提供。
4. **拆到哪为止（票 #186）。** 只拆出封面下探与同包顶层判定（扩展名表、`isImageFile`/`isArchiveFile`、`DirContents`/`dirContentsOf`）；**压缩包条目缓存、快照基线留在文件源适配器里，不再继续拆**。
5. **文档边界。** 本批新出的内部模块名（取字节、解码、缓存键、封面下探、在飞登记、重试策略、指针簿记）**不补进 `GLOSSARY.md`**；`docs/spec/browsing.md` 也不为「进目录首屏的取消按失败记账」补例外说明。

## 后果

- 规格与术语表在这一层与代码不同步：看文档找不到这些内部模块名，需要看代码或本记录。这是有意接受的——规格只写判据与边界，内部结构不进规格。
- 判据不变由既有测试兜住：本批收尾时全量单测 1837 条通过、lint 通过。
- 后续若还要继续拆文件源适配器（快照基线、压缩包条目缓存），需另立票重新评估，并沿用第 2 条约束。
